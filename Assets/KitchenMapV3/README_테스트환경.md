# KitchenMapV3 — 로컬 수정 테스트 초안

2026-09-15 · 담당: 송원석 · 브랜치: `feat/sws-kitchenmap-v3`

이 패키지는 부엌맵 생성·플레이 설정·검사 도구다. 완성 맵이나 전체 구간 완주 보증판은 아니다. 기존 팀 코드·팀 씬·프로젝트 설정 변경은 포함하지 않는다.

## 맵 열기

1. Unity **2022.3.62f3**로 이 브랜치의 프로젝트를 연다. 통합 검증 기준 develop은 `c8f72ae72d87f70c2f0f3383cf7fe29c31c08b84`이며 Built-in 렌더러다.
2. 기존 씬의 작업을 별도로 보관하고, **File > New Scene에서 Empty**를 선택한다. 씬은 하나만 연다. 기본 카메라가 있는 Basic 씬이나 팀 SampleScene에서 생성하지 않는다.
3. 새 씬을 `Assets/KitchenMapV3/Scenes/내테스트.unity`에 저장한다. 폴더는 필요하면 만든다.
4. `Tools/KitchenMapV3/2. Build All (T0 블록아웃+질감+자연화)` 실행.
5. `Tools/KitchenMapV3/3. Setup Play (도형 3종 + 카메라)` 실행. 콘솔 오류가 없는지 확인하고 씬을 저장한다.
6. Play를 누른다. **WASD 이동, Space 점프, Tab 도형 전환**. 카메라는 우클릭 드래그·Q/E·Z/C 회전, V 리셋, 휠 줌을 사용한다.

기존 시험 씬을 교체할 때는 새 Empty 씬에서 다시 생성하는 것이 가장 명확하다. 이름만 같은 오브젝트를 일괄 삭제하거나 팀 씬을 정리하지 않는다. 도구는 `V3_Owned` 표식이 없는 동명 루트/플레이어, 비활성·복수 루트, 다른 경로 및 additive 씬을 검사해 작업을 거부한다. 표식 도입 전 씬은 그대로 재사용되지 않을 수 있다.

## 이번 수정

- 계단: 단차 0.8U, 아일랜드 12단·넓은 발판·계단참, 조리대 12단 및 연결 경로/CP02/방향 표시 조정.
- 생성된 세 플레이어에 `V3_WallSlip`과 `V3_GroundContactRelay` 적용. 벽 마찰에 의한 점프 막힘을 완화하고 루트 Rigidbody의 실제 충돌을 기존 자식 접지 컴포넌트에 전달한다. 팀 접지 코드는 변경하지 않는다.
- P5: 판 렌더러 참조 저장, 비활성/파괴/콜라이더 상태 정리, 해당 판 지지체의 실제 접촉을 이용한 눌림 판정, 센서 위치 보완.
- 카메라 충돌 당김·입력 양보, 생성 도구의 소유권 보호·실패 반환, 감사 및 배치 실패 전파 보완.
- 생성 재질은 활성 렌더 파이프라인에 맞춘다. URP 패키지를 이 변경에서 추가하지 않는다.

## 통합 검사 결과와 한계

Unity 2022.3.62f3, 위 develop 소스와 이번 코드의 격리된 통합본에서 실행했다.

| 검사 | 결과 |
|---|---|
| 편집 회귀 | 53 PASS / 0 FAIL |
| 플레이 회귀 | 48 PASS / 0 FAIL, 해당 시험 런타임 오류 0 |
| P5 접촉·무게·게이트 논리 | 81 PASS / 0 FAIL, 해당 시험 런타임 오류 0 |
| 소유권 보호 | 35 PASS / 0 FAIL |
| 순차 게이트 | G1·G3 우회 잠금 유지, G2 정상 순서 해제 |
| 계단 기하 | 27개 계단/계단참 박스, 0.005U 초과 정적 관통 0쌍 |
| Windows 빌드 | 성공, 오류 0. Telemetry 설정 파일 부재 경고 1 |
| 계단 기본 설정 | 96 PASS / 0 FAIL — 아래 추가 점프 조건 포함 |

**알려진 문제: 세모는 아일랜드 첫 계단참 연결부에서 멈출 수 있으며, 추가 점프 후 진행한다.** 재현 위치는 대략 Unity `(40.000, 2.989, 53.361)`이다. 자동 시험의 연속 등반 성공에는 정지 후 추가 점프가 포함돼 있으므로 걸림이 완전히 해결됐다는 뜻이 아니다.

마찰 OFF 대조군을 포함한 물리 시험 전체는 182 PASS / 4 FAIL이다. 4 FAIL은 OFF에서 네모·세모의 두 계단 등반이며 기본 설정과 구분한다. 물리 시험은 이동 속도와 팀 점프 큐를 사용한 자동 입력으로, 실제 키보드 완주 증거가 아니다.

P5 논리 성공은 판에 몸을 배치한 검사다. 처음부터 P5 출구까지 실제 조작 완주, 병목 구간 통행, 휠/투석기의 모든 입력 조합 및 최신 포털/롤 모드의 팀 카메라 연동은 미검증이다. 팀 `PlayerFollowCamera`를 맵 전용 카메라로 대체하므로 해당 API에 의존하는 기믹을 추가할 때 별도 확인이 필요하다.

## 생성 파일과 주의점

- 씬·자동 시험 하네스·Windows 실행본·로그는 이 커밋에 포함하지 않는다. 위 메뉴로 각자 시험 씬을 만든다.
- `.mat`은 포함하지 않으며 `Build All`이 `Assets/KitchenMapV3/Materials/`에 생성한다. 해당 폴더와 `V3_Reports/`, 개인 시험 씬은 자동으로 업로드 대상이 되지 않는다.
- 팀 생성기가 실행 중 기존 DoorSystem/DreamThreadSystem 등의 재질을 다시 저장할 수 있다. 발생한 팀 자산 변경은 이 맵 변경에 함께 커밋하지 않는다.
- `4. Audit + T0 Measure`는 진단 메뉴다. 감사 PASS만으로 실제 완주나 모든 접촉의 정상 동작을 단정하지 않는다.
- 투석기 `2c`는 실험 메뉴이며 기본 `Build All` 체인에서 제외돼 있다. 카트 도킹 토글도 완성된 플레이 기믹을 뜻하지 않는다.
- 리포트는 프로젝트의 `V3_Reports/`에 생성된다. 환경변수 `V3_REPORT_DIR`로 시험 출력 경로를 바꿀 수 있다.
