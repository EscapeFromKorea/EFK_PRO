## 1. 기획 의도 / 목적

역할을 특정 도형(구/정육면체/정사면체)에 고정하지 않고, 참가자가 **원하는 위치에서 자유롭게
선택**한다. 핵심 설계 원칙은 "서로 다른 화면에 서로 다른 정보 조각을 배치해, 게임 내
텍스트/음성 채팅 기능 없이도 참가자가 실제 대화로 정보를 교환하게 만든다"는 것이다.

- **CH7**: 책 담당은 참고 자료(생물학 개념·분류표)를, 컴퓨터 담당은 자기 화면의 문제·선택지를
  본다. 서로의 화면을 볼 수 없으므로 책 담당이 자료를 읽어주고 컴퓨터 담당이 답을 골라
  제출해야 한다.
- **CH8**: 같은 책 패널 기능을 재사용해 조합법을 표시한다. 다만 재료 투입·조합 판정 자체는
  이 시스템이 아니라 **가상 시약 혼합 장치**(별도 PRD)가 처리한다. 이 시스템은 책 표시와
  역할 슬롯만 제공한다.
- 이 문서는 **역할 슬롯 관리(선택/중복 배정 방지/반환)**와 **단서·문답 UI 프레임**만 다루는
  CH7·CH8 공용 기반 인프라다. 문항/조합법 등 실제 콘텐츠 데이터, 전력 게이지, 조합 판정,
  관리자 감시는 각각 별도 기믹(전력 유지 장치, 혼합 장치, 관리자 장치)의 책임이다.
- **CH2 스코프 제외(확정)**: 원본 문서 제목은 "CH2·7·8"이지만, 본문·용어·구성표를 대조한 결과
  CH2(격리실 협력 구출 장치)는 이 시스템을 쓰지 않는 것으로 확정한다. 근거: (1) CH2는 역할이
  참가자가 위치를 골라 선택하는 것이 아니라 "수색 레버로 연 진입점을 첫 유효 참가자가 통과하면
  자동으로 격리 대상이 되는" 이벤트 기반 배정이다. (2) CH2 문서에는 "역할 위치"/"역할 반환" 같은
  이 시스템 고유 용어가 전혀 등장하지 않고, 자체 트리거(`C2_CAPTURE`, `C2_CLUE_1~3`, `C2_MAP`)로
  완결되어 있다. (3) "함께 사용하는 기믹" 상호 링크로 교차 검증을 시도했으나 CH7 서버실 전력
  유지 장치처럼 이 시스템을 명백히 쓰는 문서조차 링크 목록에 이 문서를 걸어두지 않아 — 그 목록은
  완전한 의존관계 그래프가 아니라 작성자가 임의로 붙인 참고용 목록임을 확인했다(증거 능력 없음).
  제목의 "CH2"는 컴포넌트 공유가 아니라 "정보를 안팎으로 나눠 대화로 전달한다"는 **설계 원칙**을
  공유한다는 뜻으로 해석한다.

## 2. 동작 시나리오

1. 참가자가 역할 위치(책/컴퓨터/전력 — CH7, 책/혼합/감시 — CH8)에서 상호작용하면 해당
   역할을 맡는다. 도형 종류에 따른 역할 제한은 없다. 이미 다른 참가자가 맡은 역할은 선택할
   수 없다("{이름}님이 사용 중입니다" 표시, 기존 역할 보존).
2. 자기 역할 위치에서 다시 상호작용하면 그 역할의 패널(책 패널 또는 문답 단말)이 열린다.
3. **CH7**: 컴퓨터 담당이 문제/선택지를 읽고 선택 버튼을 누른 뒤 "제출"을 누른다(선택만으로는
   제출되지 않는다). 정답이면 "정답입니다" → 다음 문항, 오답이면 "자료를 다시 확인하세요" →
   선택만 초기화하고 같은 문제 유지. 마지막 정답 시 전체 성공 1회 발신.
4. 전력 부족 시(서버실 전력 유지 장치가 발신하는 게이트) 제출 버튼만 비활성화된다. 책 읽기·
   문제 열람은 계속 가능하고, 이미 맞힌 문항은 보존된다.
5. 개인 복귀(추락 등)나 패널 닫기/거리 이탈/역할 변경 시: 패널 종료, 미제출 선택 취소, 이동
   입력 복원. 역할 자체와 진행 상태(맞힌 문항)는 유지된다.
6. **(팀 회신) 자발적 반환과 이탈은 다르게 처리한다.**
   - 자발적 반환(Esc "사용 종료"): 점유만 풀린다. 퍼즐은 **멈추지 않는다** — 제한시간·전력
     감소·관리자 행동이 계속된다. "필수 역할 공석" 개념은 없다.
   - 참가자 이탈(튕김/나감): 그 사람의 점유를 풀고 챕터 전체를 정지한다(재접속 대기). 전원이
     돌아오면 "재개 대기"가 되고, 시작 담당자가 "이어서 시작"(Enter)을 눌러야 재개된다 — 재접속
     순간 위험 장치가 바로 움직이지 않게 하기 위함. 완료한 단계는 보존, 진행 중이던 단계의
     미제출 입력만 지운다.
   - 사물은 1인 1개. 다른 사물을 쓰려면 먼저 Esc로 내려놓아야 한다. 서버실 배선
     (`allowMultipleUsers`)만 여럿이 함께 쓴다.
   - 단독 사물의 화면을 열어 둔 동안 그 참가자의 이동·점프가 잠긴다(`PlayerMover.InputLocked`).
7. 챕터 종료/전체 재시작 시 역할은 전부 해제되고, 데이터는 첫 문항/책 첫 페이지로 초기화된다.

## 3. 컴포넌트 / 스크립트 설계

저장소 공통 발신자-수신자 분리 패턴(`Assets/CLAUDE.md`)을 따른다. 예상 폴더:
`Assets/RoleClueTerminalSystem/`.

- **`RoleSlot`** (역할 위치, 트리거) — 상호작용 지점 하나당 1개. 역할 ID(`Book`/`Computer`/
  `Power`/`Mixer`/`Monitor` 등 챕터별로 다름)와 현재 소유자(참가자 ID, 비어있으면 `null`)를
  들고 있다. 상호작용 시 매니저에 배정을 요청한다.
- **`RoleAssignmentManager`** (챕터당 1개, 슬롯들의 공유 상태) — 중복 배정 거부, Esc 사용 종료,
  Tab 전환 시 이전 캐릭터 화면 닫기, 개인 복귀 시 화면 닫기(`RespawnController.PlayerRespawned`
  자동 구독), 이탈/재접속/재개(`NotifyParticipantLeft`/`Rejoined`, `SetStartOwner`,
  `RequestResume`). 이탈 **감지**는 하지 않는다 — 세션/넷코드 계층이 호출할 창구만 있다.
  - 정지 신호: **`IParticipantPauseReceiver.SetParticipantPaused(bool)`** — 이탈 시에만 true.
    구독(`Subscribe`) 즉시 현재 상태로 1회 호출된다. 전력 유지 장치·혼합 장치·관리자·
    `QuizTerminal`이 구독해 입력·타이머·위험 장치를 멈춘다.
  - 챕터 초기화: **`ResetChapter()`** — 역할 전부 해제 + C# 이벤트 `ChapterReset` 발신. 각 장치가
    구독해 스스로 초기 상태로 돌아간다(책 첫 페이지, 문답 첫 문항 등). 세션 정지 상태·플레이어
    위치는 건드리지 않는다(위치 복귀는 호출하는 챕터 컨트롤러 몫).
- **`BookPanel`** — 역할별 자료 표시. 페이지 이전/다음/닫기. CH7·CH8 공용으로 재사용
  (본문 콘텐츠만 챕터별로 다름).
- **`QuizTerminal`** (CH7 전용) — 문제·선택지·제출·정오답 판정·문항 진행. 제출 가능 여부는
  외부 게이트(전력 유지 장치가 발신)를 구독하는 bool 프로퍼티/이벤트로 받는다 — 정확한 신호
  계약(강타입 인터페이스 vs UnityEvent)은 전력 유지 장치 PRD에서 확정한다(`WindupAxle`
  선례처럼 연속 상태는 인터페이스, 이산 이벤트는 `UnityEvent` 병행이 유력한 후보).
  → **확정(PR #106)**: `SetSubmitGate(bool)` 직접 호출. 패널 액션 훅(`actionLabel`/`actionKey`
  기본 Space/`onActionRequested`)으로 다른 시스템의 동작("실험 시작")을 패널에 얹고,
  `SetFeedback(string)`으로 거부 사유를 피드백 줄에 띄운다.
- CH8은 `BookPanel`만 재사용하고 `QuizTerminal`은 쓰지 않는다(조합 판정은 혼합 장치 소관).

## 4. 확정값 / 기본값

| 항목 | 확정 내용 |

| 역할 배정 방식 | 위치 상호작용으로 선택. 도형 종류에 따른 고정 역할 없음(확정) |

  HUD에 노출 금지(확정) |
| 정전 중 동작 | 책/문제 열람은 계속 가능, 제출만 잠김. 이미 맞힌 문항은 유지(확정) |
| 개인 복귀 영향 | 역할·진행 상태 보존, 미제출 선택만 취소(확정) |

| 입력 키 | 상호작용 E, 사용 종료 Esc, 이어서 시작 Enter, 문답 선택 1~9·제출 Enter, 책 페이지 ←/→, 패널 액션 Space. 카메라가 커서를 잠가 OnGUI 버튼은 못 누르므로 전부 키보드 |

## 6. 완료 조건 대비 검증

| ID | 조작 | 기대 |
|---|---|---|
| R-01 | A/B가 동시에 같은 역할(책) 선택 | 한 명만 소유 |
| R-02 | A가 책 소유 중 B 소유 컴퓨터 선택 | 변경 거부, A의 책 소유 유지 |
| R-03 | A 반환 → B가 그 역할 선택 | 순서대로 해제/배정 처리, A의 이전 입력은 무효 |

| R-06 | 정전 중 마지막 답 제출 시도 | 오답 처리 없이 거부(제출 자체가 막힘) |

| R-08 | 실제 두 화면에서 책/문제 확인 | 서로의 상세 화면·정답 데이터가 노출되지 않음 |
