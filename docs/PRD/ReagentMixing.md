# 가상 시약 혼합 장치 (Reagent Mixing) — PRD

> 독립 신규 기믹. 실험실 CH8 전용. 출처: Notion "요구사항명세서" —
> `[실험실 CH8] 가상 시약 혼합 장치`.
> 상태: **1차 구현 완료 + 그레이박스 테스트 방 플레이테스트 통과(2026-09-26).** 코드는
> `Assets/ReagentMixingSystem/`. 구현·플레이테스트 중 사용자 결정으로 바뀐 사항(조합식 랜덤화, 판정 시점,
> "[Space] 실험 시작" 폐지 등)을 이 문서에 역반영했다 — 원문과 달라진 곳은 "(변경 2026-09-26)"으로 표시한다.
> `docs/PRD/ManagerSurveillance.md`(CH8 관리자 감시·수면·열쇠)가 이 문서의 완성물을 소비한다 — 두 문서는
> 한 쌍으로 읽는다.

## 1. 기획 의도 / 목적

책의 조합 순서와 혼합대의 재료 표식을 참가자들이 **말로 연결**하게 만드는 협동 퍼즐이다.
버튼 기반 재료 선택/투입, 버퍼, 오조합 처리, 완성물 권한만 다루며 **물리 붓기·유체 시뮬레이션·
실제 약물 조제는 구현하지 않는다**(가상 재료, 실제 의약품과 무관).

- 책 표시는 `docs/PRD/RoleClueTerminal.md`의 `BookPanel`을 그대로 재사용한다 — 조합법
  텍스트만 CH8 전용 콘텐츠로 바꾼다(시도마다 자동 작성, §3).
- 관리자 감지·잡힘·수면·열쇠는 이 문서의 책임이 아니다. 완성물이 만들어진 뒤 "사용 요청"을
  보내는 것까지가 이 문서의 역할이고, 그 요청을 수락할지·수면을 확정할지는
  `ManagerSurveillance`가 판정한다.

## 2. 동작 시나리오

1. 책 담당은 조합법을 읽고, 혼합 담당은 혼합대에 있는 재료의 이름과 표식을 말해 준다.
   **조합법은 시도마다 무작위로 바뀐다**(변경 2026-09-26, §4 "조합식").
2. 책 담당의 안내에 따라 혼합 담당이 재료를 선택한다. 선택은 강조만 하고 투입되지 않으며,
   다른 재료로 바꿀 수 있다. "투입"(Enter)을 눌러야 한 번씩 실제로 들어간다.
3. 투입한 재료는 버퍼(진행칸)에 순서대로 쌓인다. **중간 투입은 판정하지 않는다** — 세 번째 칸을 채우는
   투입에서 순서 전체를 한 번에 판정한다(변경 2026-09-26, 원문은 투입마다 즉시 판정). 틀리면 "조합이 맞지
   않습니다. 혼합물을 비웠습니다"를 표시하고 버퍼/선택을 모두 지운다 — 재료는 무제한 재사용 가능하고 책
   내용(조합식)은 그대로 유지된다.
4. 정답 순서로 세 칸을 채우면 완성 상태가 되어 병이 표시되고, **팀 공유 완성물 권한 1개**가
   생성된다. 이후 투입/비우기는 잠긴다. 완성만으로 관리자가 잠들지는 않는다.
5. 참가자가 관리자에게 다가가면(사용 지점은 관리자에 붙어 함께 움직인다) "완성물을 사용해 관리자를
   재우기"가 표시된다. 상호작용(Ctrl)하면 `ManagerSurveillance`로 사용 요청을 보낸다.
6. 수면 수락 시 완성물 권한이 소모되고 병 표시가 "사용 완료"로 바뀐다. 거부 시(예: 거리가 멀거나
   이미 수면 중이거나 팀 실패가 확정된 경우) 권한은 보존되고 거부 이유가 표시된다.

## 3. 컴포넌트 / 스크립트 설계

폴더: `Assets/ReagentMixingSystem/`.

- **`MixingStation`** (혼합대, 상태 보유자) — `RoleSlot`(roleId `"Mixer"`)에 붙는 패널.
  재료 3개(`R_L`/`R_N`/`R_V`), 선택 표시, 투입, 비우기, 진행칸 3개, 완성 병 시각물을 갖는다. 정답
  순서는 화면에 노출하지 않는다(판정에만 존재).
  - **입력은 키보드 패널**(`QuizTerminal`과 같은 관례 — 카메라가 커서를 잠가 OnGUI 버튼을 못
    누른다): `1~3` 재료 선택, `Enter` 투입, `Backspace` 비우기. 패널 표시·입력 조건은
    `RoleSlot.CanShowTo(조작 중인 참가자)`.
  - ~~패널 액션 훅("[Space] 실험 시작")~~ — **폐지(변경 2026-09-26).** 감시 시작이 "구역 진입 자동"으로
    바뀌어(`ManagerSurveillance.md` §3) 혼합대에 시작 버튼을 둘 이유가 없어졌다. 훅 코드도 제거했다.
  - **완성물 권한 = 혼합대 안의 카운터**(`HasToken` / `ConsumeToken()` / `TokenUsed`). 원안의 별도 컴포넌트
    `TeamCompletionToken`은 만들지 않았다 — 운반·분실이 없고 챕터 재시작에 0이 되는 순수 카운터라, 나누면
    "병은 있는데 권한은 0" 같은 두 벌 진실만 생긴다.
  - **시도·조합식·책 본문 관리**(변경 2026-09-26): 시도 번호(`Attempt`, 처음 1)를 들고, 새 시도마다 재료
    전체의 순열 중 **직전 시도와 다른 순서**를 무작위로 골라 정답으로 삼는다. 그 순서로 `BookPanel.pages`를
    다시 쓴다(RoleClueTerminal 파일은 수정하지 않고 public 필드에 값만 넣는다). 책 본문은 재료의 이름이 아니라
    **색·표식**("주황 원")으로 쓰여, 혼합 담당이 재료 이름·표식을 말로 연결해야 한다.
  - **`RoleClueTerminal` 연동**: `slot.PanelClosed` → 미제출 선택만 취소.
    `IParticipantPauseReceiver` 구현 → 이탈 정지 중 입력 차단 + 미제출 선택 취소(버퍼 유지).
    `slot.manager.ChapterReset` 구독 → 버퍼·완성 병·선택·완성물 권한 초기화 **+ 새 시도 시작**(조합식·
    책·완성물 번호 갱신).
- **`ManagerUsePoint`** (`C8_USE`, 발신자) — **Ctrl(`LeftControl`) 키** 상호작용(E는 `RoleSlot`·`WiringPort`·
  `SnapBlock`·`MovablePortalPanel`과 겹쳐 분리) 시 `onUseRequested(요청자)`를 발신한다. 역할 사물이 아니다 —
  점유 없이 팀원 누구나 쓴다. 완성물이 없으면 안내만 표시하고 요청 자체를 보내지 않는다. 결과 문구는
  관리자 쪽이 `SetFeedback`으로 돌려준다.
  - **관리자의 자식으로 배치한다**(확정 2026-09-26 — 사용 거리 U는 요청자↔관리자, `ManagerSurveillance.md`
    §4). 관리자와 함께 움직여 "등 뒤로 몰래 다가가 쓰는" 구조가 된다.
  - **콜라이더를 두지 않고 거리로 잰다.** 관리자는 kinematic Rigidbody라 자식 트리거가 관리자 compound에
    합쳐져 잡힘 판정이 "사용 범위 진입"을 잡힘으로 읽을 수 있다. `promptRadius`(안내 범위)와 관리자 쪽
    `useDistance`(판정)는 같은 값으로 둔다.
  - 걸어서 관리자까지 가야 하므로, 사물 화면을 연 참가자는 Esc(사물 내려놓기)나 Tab으로 화면을
    닫아야 움직일 수 있다(`RoleClueTerminal.md` §4 "Esc의 이중 의미"). 내려놓아도 버퍼·완성물은
    유지된다.
- **책 표시**: `docs/PRD/RoleClueTerminal.md`의 `BookPanel` 재사용. 본문은 `MixingStation`이 시도마다 작성한다.
- **연결 방향**: `MixingStation`·`ManagerUsePoint`는 `ManagerSurveillance`를 참조하지 않는다 — 방향은 늘
  관리자 → 혼합대다. 관리자 쪽 컨트롤러가 요청을 구독해 수락/거부를 판정하고 `ConsumeToken()`을 부른다.
- **텔레메트리**: `ch8_mix_*`(선택·투입 결과·비우기·조합식·권한 소비·초기화), `ch8_use_*` 이벤트를
  Grafana/Loki로 상시 보낸다(`{job="efk-pro", name=~"ch8_.*"}`).

| 입력 키 | 혼합대 패널 `1~3` 선택 / `Enter` 투입 / `Backspace` 비우기, 사용 지점 `Ctrl`(확정 2026-09-26). ~~`Space` 실험 시작~~ 폐지 |

| 조합식 | **시도마다 무작위**(변경 2026-09-26) — 재료 전체의 순열 중 직전 시도와 다른 것. 오조합은 같은 시도라 조합식이 바뀌지 않는다(바뀌면 협동 퍼즐이 아니라 운이 된다) |

| 완성물 이름 번호 | 시도 번호를 따른다 — `안정화 용액 S-01` → `S-02` …, ID `SEDATIVE_S01` → `SEDATIVE_S02` …(변경 2026-09-26). 책 제목·혼합대 패널 제목·완성 병 표시에 쓰인다 |
| 완성 조건 | 정답 순서로 재료 3개 투입 |
| 완성 후 잠금 | 투입/비우기 거부(완료 뒤 비우기 거부) |
| 완성물 성격 | 팀 공유 권한 1개. 사용 가능한 참가자는 팀원 전체 |
| 개인 낙하/패널 닫기/역할 교체 영향 | 버퍼·완성물 유지, 미제출 선택만 삭제 |

## 6. CH8 재료·책 콘텐츠 (구성안)

| 재료ID | 혼합대 표시 이름 | 색 | 책 표기 색 이름 | 표식 |
|---|---|---|---|---|
| R_L | 루멘 | 파랑 | 파란 | 삼각형 |
| R_N | 노바 | 주황 | 주황 | 원 |
| R_V | 베일 | 흰색 | 흰 | 사각형 |

조합식은 시도마다 무작위(§4). 책 본문은 `MixingStation`이 자동 작성한다 — 1페이지는 제목(`안정화 용액
S-NN`)과 첫 번째 재료(예: "첫 번째 재료: 주황 원."), 2페이지는 나머지 순서(두 번째 … 마지막)와 "순서가 틀리면
처음부터 다시 넣어야 한다", 3페이지는 고정 문구(완성된 용액은 관리자 사용 지점에서 사용해야 하며 혼합 완료만으로는
작동하지 않고, 수면 후 열쇠를 회수해 출구로 이동해야 한다). 책 담당 화면에는 혼합대의 현재 선택을 공유하지
않는다 — 혼합 담당이 표식을 말하고 책 담당이 다음 순서를 전달하는 구조를 강제한다.

## 전체 재시작 처리

원본 문서가 명시한 표준 절차다(실험실 계열 문서 공통 5단계):

1. 새 입력·피해·예약된 동작을 중지한다.
2. 현재 시도를 종료해 이전 시도의 지연 입력을 무효화한다.
3. 대상자의 로프·탑승 등 이동 제어를 해제하고 안전한 시작 위치로 이동한다.
4. 이 챕터의 장치·문제·권한을 초기 상태로 복원한다. 다른 챕터의 진행은 보존한다.
5. 안전 복귀 완료를 확인한 후 준비 상태로 돌아간다. 개인 복귀는 본문에 지정한 항목만
   초기화한다.

이 기믹에서는 4단계에 "새 시도 시작(조합식·책·완성물 번호 갱신)"이 포함된다.
