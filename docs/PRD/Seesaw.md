# 시소 (Seesaw) — PRD

> 독립 신규 기믹. 사용자가 구두로 전달한 원본 명세를 저장소 PRD 형식으로 옮기고, 2026-09-07
> 사용자와 상의해 확정한 4개 항목(필수/선택 경로, 레일카 연동 범위, 협동/솔로 여부, 고정용
> 오브젝트의 정체)을 반영했다.
> 상태: **1차 구현 완료(에디터 생성기 `SeesawSystem/Editor/SeesawMenuItem.cs`), 씬 배치·
> 플레이테스트 전.** §4에서 결정한 대로 런타임 스크립트는 없다.

## 1. 원본 기획 요구사항 (참고용 원문)

```
기능:
올라간 물체의 무게와 충돌 힘에 따라 기울어지는 자유 물리 장치다.

요구사항:
- 중심축을 기준으로 양쪽 방향으로 회전한다.
- 플레이어와 블록의 무게 차이가 기울기에 반영된다.
- 빠르게 떨어진 블록이나 레일카의 충격으로 반대편 물체를 발사할 수 있어야 한다.
- 정사면체 또는 블록을 아래에 끼워 특정 각도로 고정할 수 있어야 한다.
- 최대 회전 각도, 질량, 회전 저항을 조절할 수 있어야 한다.

주요 활용:
- 임시 경사로
- 플레이어 발사대
- 다리
- 카운터웨이트

완료 조건:
- 단순히 올라섰을 때는 기울고, 충격을 주면 발사대처럼 작동한다.
- 크기 변형으로 플레이어의 무게가 바뀌면 결과도 달라진다.
- 정사면체나 블록으로 임의 각도를 유지할 수 있다.
```

사용자 확인(2026-09-07):
1. **경로 성격** — 선택 경로/자유 배치형. 필수 통과 경로가 아니므로 발사 세기에 최소 도달
   보정(투석기식 결정론) 같은 안전장치는 필요 없다.
2. **레일카 연동** — `docs/PRD/RailCart.md`가 "블록을 실어 시소에 충돌"을 이미 활용 사례로
   적어뒀지만, 이번 PRD는 레일카와 짝을 맞추지 않고 **독립 기믹으로 우선 설계**한다. 실측 후
   부족하면 그때 별도로 조정한다.
3. **협동/솔로 — 하이브리드로 확정.** 협동도 가능해야 하지만, **딱딱 블록(SnapBlock)을 쓰면
   혼자서도** 완결되어야 한다.
4. **고정용 오브젝트** — 저장소에 정사면체 "프롭" 오브젝트는 없다(정사면체는 플레이어 도형으로만
   존재). 끼우는 대상은 **정사면체로 변신한 플레이어 자신 + `SnapBlockSystem`의 딱딱 블록**이며,
   둘 다 이미 있는 오브젝트다 — 시소 전용 프롭을 새로 만들지 않는다.

## 2. 기획 의도 / 목적

원문이 스스로를 "**자유 물리 장치**"라 못박은 유일한 기믹이라는 점이 이 PRD 전체를 관통한다.
저장소의 다른 기믹은 전부 "무게/충돌을 스크립트가 판정해서 반응을 계산"하는 패턴이다
(`PlayerWeight.Of` 임계 비교, 운동량 AND 조건 등, `Assets/CLAUDE.md` "무거워서 못 한다류" 절
참고). 시소는 그 판정 자체를 스크립트가 하지 않고 **PhysX가 대신 하게 두는 것**이 기획 의도와
정확히 일치한다.

**핵심 결정: Unity `HingeJoint` + dynamic `Rigidbody` 하나만으로 원문의 5개 요구사항
(양방향 회전 / 무게차 반영 / 충격 발사 / 각도 고정 / 각도·질량·저항 조절)이 전부 자동으로
성립한다.** 저장소가 지금까지 만든 기믹 중 런타임 C# 스크립트가 사실상 필요 없는 첫 사례다.

- 왜 가능한가 — 다른 기믹이 자체 판정 코드를 쓰는 이유는 "결정론이 필요"(점프 도달 높이 보장,
  투석기 발사 속도 등)했거나 "특정 도형만 반응해야"(존재 자체가 트리거) 했기 때문이다. 시소는
  §1에서 확인했듯 **선택 경로**라 결정론이 필요 없고, "누가/무엇이 얼마나 무거운가"가 그대로
  물리량(질량)으로 반영되면 충분하므로 도형 판별도 필요 없다.
- `PlayerGravityOverride`가 실제 `rb.AddForce`로 중력을 대체 적용하는 구조라(코드 확인,
  `PlayerSystem/PlayerGravityOverride.cs` FixedUpdate), 무중력 버블 등으로 실효 무게가 바뀐
  플레이어도 시소 위에서 자동으로 더 가볍게 반영된다 — 무게를 다시 계산하는 코드가 필요 없다.
- `ScalingSystem/Playershapecontroller.cs`가 `rb.mass = shapeIdentity.stats.mass * scaleRatio`를
  매 스텝 직접 쓰므로(코드 확인), 크기 변형으로 바뀐 무게도 시소가 별도로 알 필요 없이 그대로
  반영된다 — 완료 조건 2번("크기 변형으로 무게가 바뀌면 결과도 달라진다")이 공짜로 성립한다.

## 3. 동작 시나리오

### 3.1 기본 구조

- `Seesaw_Root`(고정 앵커, static 오브젝트) — 중심축 위치를 잡는 빈 부모.
- `Seesaw_Plank`(자식, dynamic `Rigidbody` + `BoxCollider` + `HingeJoint`) — 실제 판.
  `HingeJoint.connectedBody = null`로 두면 월드에 고정된 축에 바로 매달리므로 별도 앵커
  `Rigidbody`가 필요 없다. `anchor`/`axis`로 중심축 위치·방향을 지정한다.
- 회전축은 판의 긴 방향과 수직인 수평축 하나 — "중심축을 기준으로 양쪽 방향으로 회전한다"를
  그대로 구현한다.

### 3.2 무게차 반영 (정적)

코드 없음. 양 끝에 있는 대상(플레이어/블록)의 실제 `Rigidbody.mass`(중력까지 포함한 실제 하중)가
지레 팔 길이를 통해 자연히 토크로 변환된다 — 무거운 쪽이 내려가고 가벼운 쪽이 들린다.
`HingeJoint.useLimits`(min/max angle)로 "최대 회전 각도"를 제한해 지면에 처박히거나 과도하게
서는 것을 막는다.

### 3.3 충격 발사 (동적)

코드 없음. 빠르게 낙하한 블록이나 레일카가 판 한쪽에 충돌하면 그 충격량이 지레를 통해 반대쪽
각속도로 전달되어, 반대쪽에 있던 물체가 튕겨 올라간다 — 실제 시소가 하는 그대로다.

`CatapultArm`은 "발사 속도는 팔의 물리 반동이 아니라 당김 비율 → 속도 결정론적 계산식"을 쓰는데
(`Assets/CLAUDE.md` CatapultSystem 절), 시소는 §1에서 확인한 대로 선택 경로라 이 결정론이
필요 없어 **순수 물리 반동을 그대로 쓴다** — 이 판단 자체가 투석기와의 핵심 차별점이다.

### 3.4 각도 고정 (쐐기)

§1에서 확인한 대로 고정에 쓰는 대상은 둘뿐이다:

- **`SnapBlockSystem`의 딱딱 블록** — 정석 **솔로** 풀이. 블록을 날라 판 아래 틈에 밀어 넣으면
  물리적으로 처박혀 그 각도를 유지한다. 블록은 두고 나서 자유롭게 이동할 수 있으므로 혼자서
  "나르기 → 배치 → 이동"까지 끝낼 수 있다.
- **정사면체로 변신한 플레이어 자신** — 정석 **협동** 풀이. 변신 중엔 그 자리에 몸으로 남아
  받쳐야 각도가 유지되므로(다른 곳으로 이동 불가), 다른 플레이어가 그 위를 건너가야만 의미가
  있는 협동 구간이 자연히 성립한다.

둘 다 순수 충돌 판정이라 시소 쪽은 "누가 끼어 있는지" 알 필요가 없다 — `RailCartCargoBay`가
"아무 Rigidbody나 질량 합산"하는 것과 같은 철학(`docs/PRD/RailCart.md` §3.3)이며, 시소 전용
프롭도 새로 만들지 않는다.

### 3.5 레일카 연동

§1에서 확인한 대로 **독립 기믹으로 우선 설계**한다. `RailCart`는 이미 항상 dynamic
`Rigidbody`이고(`RailCart.md` §3.2), 시소도 일반 물리 충돌만 받으므로 교차 폴더 수정 없이
자동으로 맞물린다. 실측 시 충돌 세기가 부족하면 그때 `RailCartSystem` 쪽 상수 조정을 하드 룰에
따라 사용자 허가 하에 별도로 진행한다(§6 TBD).

## 4. 컴포넌트 / 스크립트 설계

- **물리 로직을 짜는 런타임 `MonoBehaviour`: 없음(확정).** 원문의 요구사항 전부가 Unity 내장
  `HingeJoint` + `Rigidbody` 필드로 충족된다. (2026-09-08 추가: `SeesawTuningNotes`는 예외지만
  로직이 아니라 인스펙터 hover 설명용 주석 컴포넌트다 — Update/FixedUpdate 없이 필드에
  `[Tooltip]`만 달아 위 Rigidbody/HingeJoint 값을 왜 그렇게 잡았는지 보여준다. 실제 값을
  복제하지 않으므로 드리프트 위험 없음.)
- 유일한 물리 로직 신규 코드는 에디터 생성 도구 `SeesawSystem/Editor/SeesawMenuItem.cs`
  (`Tools/SeesawSystem/Create Seesaw`) — 저장소 관례(`RotatingPlateMenuItem`,
  `HourglassMenuItem` 등)를 따라 `Seesaw_Root` + `Seesaw_Plank` 계층과 위 컴포넌트 조합을 한
  번에 생성한다. 판 콜라이더에는 마찰이 충분한 `PhysicMaterial`을 붙여 탑승자가 미끄러지지
  않게 한다(씬 튜닝 대상).
- 지금은 만들지 않는 것(YAGNI) — 기울기 시각 피드백, 잠금/발사 `UnityEvent` 훅. 원문 요구사항에
  없고, 필요해지면 그때(플레이테스트 후) 추가한다.

## 5. 확정값 / 기본값 (전부 씬 튜닝 대상)

| 파라미터 | 위치 | 설명 |
|---|---|---|
| `Rigidbody.mass` | `Seesaw_Plank` | 판 자체 질량 — 무거울수록 같은 하중차에도 덜 기운다 |
| `Rigidbody.angularDrag` | `Seesaw_Plank` | 회전 저항 |
| `HingeJoint.limits.min/max` | `Seesaw_Plank` | 최대 회전 각도(좌우 대칭/비대칭 모두 가능) |
| `HingeJoint.anchor` / `axis` | `Seesaw_Plank` | 중심축 위치/방향 |
| `PhysicMaterial.dynamicFriction` 등 | 판 콜라이더 | 탑승자가 미끄러지지 않을 최소 마찰 |

## 7. 완료 조건 대비 검증

| 완료 조건 | 충족 방식 |
|---|---|
| 단순히 올라섰을 때는 기울고, 충격을 주면 발사대처럼 작동한다 | §3.2·§3.3 — 같은 `HingeJoint` 물리 하나가 정적 하중(기울기)과 동적 충격(발사)을 모두 자동으로 만들어낸다 |
