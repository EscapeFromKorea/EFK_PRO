# 경로 추격자 (Path Chaser) — PRD

> 독립 신규 기믹. 실험실 CH1 전용. 출처: Notion "요구사항명세서" —
> `[실험실 CH1-1] 경로 추격자`.
> 상태: **기획 단계 — PRD 작성만 완료, 구현 전.**
> 참고: `docs/PRD/ManagerSurveillance.md`(CH8)가 이 문서의 추격자 **이동/모델**을 별도
> 인스턴스로 재사용하기로 이미 전제하고 있다 — 상태(추격/잡힘)는 CH1과 CH8이 완전히 독립임을
> 이 문서와 그 문서 양쪽에서 확정한다.

## 1. 기획 의도 / 목적

달리다가 벽 앞에서 역할을 나누고(투석기로 벽 파괴), 벽을 연 뒤 카트로 추격을 끊는 장면이다.
이 문서가 새로 만드는 것은 **추격자의 경로 이동, 벽 파괴 전 이동 제한, 접촉 시 개인 복귀
요청, 종점 종료** 네 가지뿐이다 — 발사(투석기)·파괴벽·카트 물리는 전부 기존 시스템을
재사용하고 새로 만들지 않는다.

## 2. 동작 시나리오

1. 추격자 접근을 확인한 참가자들이 벽 앞 투석기로 이동한다.
2. 정육면체가 탑승하고 동료가 기존 장전·발사 조작으로 벽을 부순다.
3. 벽 뒤에서 합류한 뒤 준비된 카트 3대로 절벽을 건넌다.
4. 추격자는 경로 종점에서 팀의 기존 탈출 조건이 충족되면 추락하고, 이후로는 잡힘을
   발생시키지 않는다.
5. 도중에 잡힌 플레이어만 복귀한다. 동료의 이동과 이미 부순 벽 상태는 그대로 유지된다.

## 3. 컴포넌트 / 스크립트 설계

예상 폴더: `Assets/PathChaserSystem/`. 다른 시스템(투석기·파괴벽·레일카·출구)의 파일은
수정하지 않고 참조만 한다.

- **`PathChaserController`** (상태 보유자) — §4 상태표(대기/추격/벽 대기/종점 대기/종료)를
  구현한다. 벽 파괴 신호 전(경로 이동 상한 = 벽 앞 지점)과 후(종점까지 허용)를 구분한다.
- **`PathChaserAgent`** (추격자 이동체) — 지정 경로(웨이포인트 목록)를 따라 이동. 접촉 시
  개인 복귀 요청만 발신하고, 직접 플레이어를 조작하지 않는다(발신자-수신자 패턴). 경로 이탈이
  필요하면 외부가 넘긴 목표 지점으로만 이동한다(판단은 하지 않는다 — CH8 재사용분은 경로 전용).
- **근접 추격(2026-09-25 추가, 사용자 확정)** — 경로를 따르다 주변 `detectRadius` 안에 **보이는**
  플레이어가 있으면 가장 가까운 대상에게 수평으로 붙는다. 경로를 벗어난 지점(anchor)에서
  `leashRadius` 밖으로 달아나거나 시야가 끊기면 anchor로 돌아간 뒤 경로를 재개한다(돌아가는 중
  재추격해도 anchor 유지 — 경로에서 목줄 이상 멀어지지 않는다). 시야가 벽에 막히면 쫓지 않는다 —
  추격자는 벽을 물리적으로 통과하므로 이 검사가 "벽 파괴 전 벽 너머로 못 간다"를 지킨다. 판단은
  `PathChaserController`(CH1)가 한다.
- **접촉 → 개인 복귀 연결**: `docs/PRD/SectionRespawn.md`의 목적지 지정 개인 복귀를 재사용.
  목적지는 벽 파괴 여부에 따라 `SAFE_PRE`(벽 전) 또는 `SAFE_POST`(벽 후) 중 하나 —
  `PathChaserController`가 현재 상태를 보고 어느 `SectionSafePoint`를 넘길지 결정한다.
- **재사용, 신규 코드 없음**: 투석기 탑승/발사(`CatapultSystem`), 파괴벽(`DestructionSystem`),
  카트 3대(`RailCartSystem`), 출구 목표(기존 출구 시스템). 이 문서는 이들을 **참조만** 하며
  각 시스템 폴더의 파일은 손대지 않는다.

## 4. 확정값 / 기본값

**상태 전이표** (원본 문서 그대로):

| 현재 | 사건/조건 | 반응 | 다음 |
|---|---|---|---|
| 대기 | 유효 시작 | 예고, 시작 지연 후 경로 이동/접촉 활성 | 추격 |
| 추격/벽 대기/종점 대기 | 경로 근처(감지 반경 안, 시야 확보) 플레이어 발견 | 경로 이탈해 수평 추격, 목줄 밖·시야 상실 시 이탈 지점 복귀 후 경로 재개 | 상태 유지 |
| 추격 | 벽 앞 도달 · 벽 미파괴 | 벽을 통과하지 않고 그 지점에서 대기, 접촉은 계속 유효 | 벽 대기 |
| 벽 대기 | 벽 파괴 | 다음 경로로 이동 재개 | 추격 |
| 추격/벽 대기 | 플레이어 잡힘 | 대상에게 개인 복귀 1회 요청 | 상태 유지 |
| 추격 | 종점 도달 · 팀 탈출 조건 미충족 | 낙하 연출 대기, 후발 참가자의 이동은 막지 않음 | 종점 대기 |
| 종점 대기/추격 | 종점 도달 **및** 팀 탈출 조건 충족 | 접촉 끄기 → 추락 연출 → 종료 신호 1회 | 종료 |
| 모든 상태 | 전체 초기화 | 벽/카트/추격/출구 초기화(아래 "전체 재시작 처리" 참고) | 대기 |

| 항목 | 확정 내용 |
|---|---|
| 잡힘 처리 | 개인 복귀만(팀 재시작 아님). 벽 파괴 전은 `SAFE_PRE`, 이후는 `SAFE_POST` |
| 복귀 범위 | 개인 복귀로 벽 상태나 카트 위치를 되돌리지 않는다 |
| 벽 앞 대기 | 벽 앞에서만 기다리는 물리적 제약은 허용하지만, 투석기 조작에 들어갔다는 이유로 영구 안전 모드가 되지는 않는다(계속 잡힘 대상) |
| 종료 후 상태 | 추락한 추격자는 CH2에서 접촉/이동하지 않는다(챕터 경계 밖 상태 없음) |
| CH8과의 독립성 | 이 추격자의 이동/모델을 CH8이 재사용해도 **인스턴스와 상태는 공유하지 않는다** |
| 발사 실패 시 | 기존 카트/투석기의 회수·안전 복귀 기능으로 재시도 가능해야 하며, 이 문서가 별도 재시도 로직을 만들지 않는다 |
| 카트 회수 불가 시 | 맵 완주 검수 보류로 기록하고, 임의 순간이동을 대체 규칙으로 넣지 않는다(확정 — 편법 금지) |
| 종점 종료 조건 | 카트 도착 확인 + 팀 전체 이동 조건 충족을 함께 검사한다 — 선두 한 명만 건너도 종료되지 않도록 실제 팀 조건을 확인 |

| 파라미터 | 타입 | 설명 | 상태 |
|---|---|---|---|
| 경로 지점(웨이포인트) | `Transform[]` | 시작 → 벽 앞 정지 한계 → 절벽 종점 | 배치 시 지정 |
| 추격 속도 | `float`(U/s) | 경로 이동·근접 추격 공용 | 기본 3, 실측 필요 |
| 감지 반경 `detectRadius` | `float`(U, 수평) | 이 안에 보이는 플레이어를 쫓는다 | 기본 6, 실측 필요 |
| 목줄 반경 `leashRadius` | `float`(U, 수평) | 경로 이탈 지점 기준 추격 한계 | 기본 8, 실측 필요 |
| 시작 지연 | `float`(s) | | 미정 |
| 잡힘 영역 | 콜라이더 | | 미정, 실측 필요 |
| 안전점(`SAFE_PRE`/`SAFE_POST`) | `Transform` | 추격 경로 밖에 배치. 복귀 직후 추격자에 닿는 배치는 금지 | 배치 시 지정, **참조 없으면 시작 거부** |
| 기존 카트/투석기/벽 참조 | 참조 | 누락 시 시작 거부 | 배치 시 지정 |

## 전체 재시작 처리

원본 문서가 명시한 표준 절차다(실험실 계열 문서 공통 5단계):

1. 새 입력·피해·예약된 동작을 중지한다.
2. 현재 시도를 종료해 이전 시도의 지연 입력을 무효화한다.
3. 대상자의 로프·탑승 등 이동 제어를 해제하고 안전한 시작 위치로 이동한다.
4. 이 챕터의 장치·문제·권한을 초기 상태로 복원한다. 다른 챕터의 진행은 보존한다.
5. 안전 복귀 완료를 확인한 후 준비 상태로 돌아간다. 개인 복귀는 본문에 지정한 항목만
   초기화한다.
