> 독립 신규 기믹. 실험실 CH5 전용으로 요청됐지만 다른 챕터에도 쓸 수 있는 범용 감지기다.

> 상태: **1차 구현 완료(2026-10-04) — `Activate`/`Deactivate` 동작은 플레이 모드로 확인, 나머지 완료 조건(Z-06 시작 시
> 구역 안, Z-07 복귀, Z-09 재활성화 등)은 미확인.** 확정 사항은 2026-10-04 사용자 확인.
> 구현 메모: `Deactivate()`는 피해를 끄고 평소 이동 속도로 초기 자세까지 되돌아간다(끼임 안전 정지 유지, 확정). 되돌아가는
> 중의 `Activate()`는 복귀 후 시작하도록 보류한다(초안). 감지기 인스펙터에 함정 연결 도우미(`PeriodicTrapBase`만 받음)와
> `debugLog` 옵션이 있다.

## 1. 기획 의도 / 목적

플레이어가 보이는 함정으로 들어가기 전, 특정 지점을 밟은 사실을 **다른 기믹에 전달**한다.
이 장치는 도끼·망치·가시의 운동을 직접 구현하지 않는다 — 진입 판정과 이벤트 발신만 하고,
무엇을 켤지는 맵 담당자가 인스펙터로 연결한다. 대상은 함정·발사구·고정 레이저다.

핵심 요구는 "도형 하나가 콜라이더를 여러 개 가져도 플레이어가 본 사건은 한 번만 일어난다"이다.

## 2. 동작 시나리오

1. 플레이어가 위험 범위 **앞**에 놓인 감지 구역에 들어선다.
2. 감지기가 그 도형의 진입을 한 번 인정하고 이벤트를 낸다.
3. 이벤트에 연결된 도끼·망치·가시·발사구·레이저가 각자 시작한다.
4. 도형이 구역 안에 계속 서 있거나 구역 안에서 움직여도 이벤트는 더 나지 않는다.
5. 구역을 완전히 벗어났다가 다시 들어오면 새 진입 후보가 된다(발동 여부는 모드가 정한다).

## 3. 컴포넌트 / 스크립트 설계

저장소 공통 발신자-수신자 패턴을 따른다. 폴더: `Assets/ZoneEntrySystem/` (확정).

- **`ZoneEntryDetector`** — 보이지 않는 `BoxCollider`(트리거) 하나에 붙는 컴포넌트.
  - 구역 크기·중심·방향은 Transform과 BoxCollider로 조정한다. 플레이 중 렌더러는 없다.
    에디터에서 선택하면 경계 기즈모가 보인다.
  - **대상 식별:** 닿은 콜라이더에서 `GetComponentInParent<PlayerMover>()`로 대표 도형 Root를
    찾는다(`PathChaserCatchZone` 등 저장소 기존 방식). `Player_Mesh`·`Player_Collider` 어느 쪽이
    먼저 들어와도 같은 Root로 합친다. 태그만 `Player`이고 `PlayerMover`가 없는 물체는 무시한다.
    상자·낙석·함정 몸체는 `PlayerMover`가 없어 0회다.
  - **출력 이벤트 2개** (같은 유효 진입에서 각각 한 번씩 발생):
    - `OnValidEntry` — 인자 없는 `UnityEvent`. `Activate()` 같은 함수에 인스펙터로 연결한다.
    - `OnValidEntryPlayer` — 대표 도형 Root(`GameObject`)를 넘기는 `UnityEvent<GameObject>`.
  - **설정:**
    | 항목 | 설명 | 기본값 |
    |---|---|---|
    | 모드 | `최초 한 번`(구역 전체에서 한 번) / `새 진입마다` | **최초 한 번** (확정) |
    | 재발동 대기 시간(초) | 이벤트를 낸 순간부터 감지기 전체에 적용. 0이면 대기 없음 | **0** (확정) |
  - 대기 시간의 실제 배치값은 맵 담당이 조정한다(미정).
- **공개 메서드:** `ResetState()` — 최초 발동 여부, 도형별 점유, 대기 시간을 모두 초기화한다
  (확정). 호출은 챕터 컨트롤러나 씬 인스펙터 배선이 맡는다. 챕터 재시작 공용 신호는 새로
  만들지 않는다.
- **연결 대상 (이미 있는 진입점):** `ProjectileLauncher.Activate()`, `FixedPeriodicLaser.Activate()`
  — 둘 다 이미 돌고 있으면 아무 일도 하지 않는다(중복 입력 무시).
- **함정 쪽 변경 (확정, 이 PRD 범위):** 현재 `AxeTrap`/`HammerTrap`/`SpikeTrap`에는
  `Activate()`/`Deactivate()`와 자동 시작 끄기가 없어 씬 시작 즉시 움직인다. `PeriodicTrapBase`에
  다음을 추가한다.
  - `autoActivateOnStart` (기본 `true` — 기존 씬의 동작을 바꾸지 않는다)
  - `Activate()` — 이미 작동 중이면 무시. 도끼는 예고부터, 망치·가시는 첫 상태부터 시작한다.
  - `Deactivate()` — 신규 주기와 피해를 끄고 이동을 현재 위치에서 멈춘다
    (`docs/PRD/PeriodicTraps.md` §5의 "구간 정지" 서술과 같다).
  `PeriodicTrapSystem`은 같은 소유자의 폴더라 교차 폴더 수정이 아니다.

## 4. 들어옴·머묾·나감의 판정

1. 감지기는 **도형별로** 현재 구역 안에 남아 있는 콜라이더를 추적한다. 한 도형의 **첫** 콜라이더가
   밖에서 안으로 바뀌는 순간만 "진입"이다.
2. 그 도형의 두 번째 콜라이더가 들어오거나, 안에서 움직이거나, 콜라이더 하나만 잠깐 나갔다
   들어와도 새 진입이 아니다. **모든** 유효 콜라이더가 밖으로 나가야 점유가 끝난다.
3. 점유가 끝난 뒤 다시 들어오면 새 진입 후보가 된다. 다른 도형이 새로 들어오는 것은 별도
   후보이지만, `최초 한 번` 모드에서는 첫 발동 뒤 어느 도형도 다시 발동시키지 않는다.
4. 재발동 대기 시간은 **이벤트를 실제로 낸 순간** 시작하고 감지기 전체에 적용한다. 대기 중 들어온
   후보는 버린다. 대기가 끝나도 안에 계속 있는 도형을 자동으로 다시 발동시키지 않는다. 밖으로
   완전히 나갔다가 새로 들어와야 한다.
5. **시작 위치가 이미 구역 안인 도형**은 씬 시작과 동시에 새 진입으로 세지 않는다. 한 번 완전히
   나온 뒤 다시 들어올 때만 센다. 정식 맵에서는 시작·복귀 위치를 구역 밖에 둔다.

## 5. 복귀와 재시작

- **개인 복귀:** 도형이 구역 밖으로 순간이동하면 그 도형의 점유를 제거한다. 물리 `Exit` 이벤트가
  오지 않아도 이전 점유가 재진입을 막지 않아야 한다. 매 `FixedUpdate`에서 점유 콜라이더가 살아
  있고 구역과 실제로 겹치는지 확인해 낡은 기록을 걷어낸다.
  - 참고: `RespawnController.PlayerRespawned`(자동·수동 R·구간 복귀 모두에서 발신, 인자 = 대상
    Root)가 있지만 **복귀가 시작될 때** 발신된다. 실제 이동은 페이드 연출 뒤에 일어나므로, 이
    신호 시점에 점유를 지우면 아직 구역 안에 있는 몸이 새 진입으로 오인될 수 있다. 이 신호를
    쓸지, 실제로 구역 밖에서 확인될 때 지울지는 구현 시 실측으로 정한다(§7).
- **복귀 목적지가 구역 안에 있는 경우:** 복귀 자체를 새 진입으로 취급하지 않는다. 구역 밖으로 한 번
  나온 뒤 다시 들어와야 한다. 안전점이 구역과 겹치는 배치는 **배치 오류**로 표시한다.
- **챕터 전체 재시작:** `ResetState()`로 최초 발동 여부·점유·대기를 함께 초기화한다. 감지기만
  초기화하고 연결된 함정이 이전 사이클에서 계속 움직이는 상태를 남기지 않는다 — 연결된 장치도
  각자의 재시작 입력을 받아야 한다(`PeriodicTraps.md`의 H-06: 다음 시작은 예고 단계부터).
- **비활성화 후 재활성화:** 안에 이미 서 있는 도형을 즉시 발동시키지 않는다. 밖으로 나온 뒤
  새로 들어올 때부터 판정한다.

## 6. 맵에서 연결하는 순서

1. 위험 범위에 들어가기 **전**에 구역 시작 경계를 놓고, 종료 경계는 안전 발판 이전에 둔다. 경계가
   시작점이나 개인 복귀점에 닿지 않는지 확인한다.
2. 도끼·망치·가시는 `autoActivateOnStart`를 끈 채로 놓고, `OnValidEntry`를 각 `Activate()`에
   연결한다. 한 감지기로 여러 장치를 켜도 각 장치는 자기 중복 입력을 무시한다.
3. 같은 방식으로 `ProjectileLauncher`와 `FixedPeriodicLaser`의 `Activate()`도 연결한다. 피격과
   복귀는 감지기가 아니라 각 장치의 기존 출력(`OnHazardHit`)에 연결한다.
4. 구역을 나갈 때 **자동으로 `Deactivate()`를 호출하지 않는다.** 뒤따라오는 동료가 아직 위험
   구간에 있을 수 있다. 정지는 별도의 명시적 신호로만 한다.
5. `최초 한 번`은 한 시도에 딱 한 번만 켜야 하는 연출에, `새 진입마다`는 개인 복귀 후 같은 함정을
   다시 시도해야 하는 구간에 쓴다.

| 개인 복귀 시 점유 제거 시점(복귀 신호 vs 구역 밖 확인) | 구현 시 실측으로 정한다 (§5 참고) |
| 점유 추적 방식(트리거 콜백 vs 매 프레임 질의) | 구현 시 실측으로 정한다. 요구는 §4~5의 **결과** |

점유 추적 방식은 요구가 아니라 구현 선택이다. 참고로 저장소의 `TeamExitZone`은 "잠든
Rigidbody에는 `OnTriggerStay`가 오지 않아 판정이 멈춘다"는 이유로 트리거 콜백 대신 매 프레임
`ClosestPoint` 질의를 쓴다. 이 감지기도 같은 문제를 겪는지 실측한 뒤 방식을 정한다.

## 8. 완료 조건 대비 검증

| ID | 조작 | 기대 |
|---|---|---|
| Z-01 | 구·정육면체·정사면체 각각 구역에 진입 (콜라이더 2개 동시) | 도형마다 유효 진입 1회 |
| Z-02 | 상자·낙석·함정 몸체가 구역을 통과 | 0회 |
| Z-03 | 도형이 구역 안에 계속 서 있음 / 안에서 이동 | 1회에서 멈춤 |

| Z-06 | 씬 시작 시 도형이 구역 안에 있음 | 시작과 동시에 발동하지 않음. 나갔다 들어올 때만 발동 |

| Z-08 | 챕터 재시작 후 첫 진입 | 이전 점유·발동 기록 때문에 누락되지 않음 |
| Z-09 | 감지기 비활성 → 재활성 시 안에 서 있음 | 즉시 발동하지 않음 |
| Z-10 | 한 감지기에 도끼·망치·발사구·레이저 연결 | 각자 한 번씩 시작. 구역이 게임 화면에 보이지 않음 |
| Z-11 | `autoActivateOnStart`를 끈 함정, 감지기 없이 씬 시작 | 함정이 움직이지 않음. `Activate()` 뒤에 시작 |
