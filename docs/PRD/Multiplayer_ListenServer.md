## 1. 기획 의도 / 목적

지금은 한 PC에서 `Tab`으로 세 도형(구/정사면체/정육면체)을 번갈아 조작하는 **1인 시험 모드**다. 협동 기믹은 "세 도형이 동시에 각자 역할을 한다"를 전제로 설계돼 있다.
이번 작업의 목적은 **세 명이 각자 PC에서 한 도형씩 맡아 같은 맵을 함께 푸는 것**이다.

- 한 명이 방을 만들면 그 PC가 서버 겸 플레이어(**리슨 서버/호스트**)가 된다. 전용 서버는 운영하지 않는다.
- 진입점은 임시 홈 화면(방 만들기 / 방 입장하기 / 설정 / 게임 종료).
- 방에서 각자 도형을 고르고 모두 준비하면 호스트가 고른 맵(개발·테스트 단계) 또는 맵 1(정식 단계)로 시작한다.
- 같은 방 안에서 마이크로 대화한다.

## 3. 현재 상태 (코드 확인, 2026-11-15)

| 항목 | 확인 내용 [코드] |
|---|---|
| 네트워크 패키지 | 없다. `Packages/manifest.json`에 Unity 내장 모듈 외 패키지가 전혀 없다(Unity 2022.3.62f3) |
| 플레이어 구성 | 씬마다 `Player_Cube`·`Player_Sphere`·`Player_Tetrahedron` 세 개가 **미리 배치**돼 있다. `PlayerControlSwitcher`가 `Tab`으로 한 개에만 조작권(`PlayerMover.IsControlled`)을 준다. 이 클래스 주석에 "멀티플레이로 확장할 때는 Tab 순환 로직만 '네트워크 플레이어 N → 슬롯 N' 배정으로 교체"한다고 적혀 있다 |
| 도형 정체 | `PlayerShapeIdentity.Kind`(Sphere/Cube/Tetrahedron). 기믹은 `GetComponentInParent<PlayerShapeIdentity>()`로 누가 닿았는지 판별한다 |
| 입력 읽는 곳 | `PlayerMover`가 `Input.GetAxis("Horizontal"/"Vertical")`을 직접 읽는다(337·338행, 545·546행 — 구/정육면체 레거시 경로와 토크 경로). `PlayerJump`는 `Input.GetButtonDown("Jump")`(45행). `Input.GetKey*/GetAxis/GetMouse*`를 쓰는 파일은 **27개** |
| **이동 방향이 카메라에 의존** | `cameraRelativeInput`(기본 true)이면 입력 벡터를 `PlayerFollowCamera.ViewYaw`(**static, 로컬 카메라 값**)로 회전한다(`PlayerMover.EffectiveInputYaw`, 696~703행). 즉 원격 플레이어의 입력을 호스트가 해석하려면 **그 플레이어의 카메라 yaw를 함께 받아야 한다** |
| 입력 잠금 | `InputGate.Blocked`(static)를 보는 파일 9개. `PlayerMover.InputLocked`가 이미 있다 |
| 시간 정지 | `Time.timeScale`을 쓰는 곳은 **두 곳**: `PauseMenuController`(`freezeTime` 기본 true)와 `LevelManager`(클리어 화면). 멀티에서 한 사람의 ESC·클리어가 전원을 멈추면 안 된다 |
| 싱글턴 | `static Instance/Current`를 가진 클래스 11개(`RespawnController`·`LevelManager`·`PlayerControlSwitcher`·`PlayerFollowCamera`·`InteractionController`·`BlockCarryController`·`CubeDockController`·`SnapBlockController`·`FrictionStickerController`·`ToyWorldLevelDirector`·`GraphicsOptions`) |
| 플레이어 탐색 | `FindObjectsOfType<PlayerMover/PlayerShapeIdentity>`로 "씬의 모든 도형"을 찾는 파일 43개. 세 도형이 **모든 피어의 씬에 존재**하는 구조라면 이 가정은 유지된다 |
| 체크포인트 | `RespawnController`가 씬에 하나, 세 도형이 공유하는 `currentZone` 하나. `R`은 "지금 조작 중인 도형"만 복귀시킨다 |
| 무작위·시간 | `Random.*` 사용 파일: `BreakableObject`·`DreamThreadController`·`FallingRock`·`MixingStation`. 낙석은 PRD(`FallingRock.md` §0.2)에 "각 클라이언트가 같은 주기로 스폰하면 어긋난다"가 이미 [TBD]로 남아 있다 |
| 물리 | `Rigidbody`가 언급되는 `.cs` 파일 수(에디터 스크립트 포함 단순 집계): `Assets/Scenes` 하위 57개, 기믹 폴더는 Catapult 8, RailCart 5, PeriodicTrap 5, SpacePortal 4, Respawn 4, Hourglass 4, DreamThread 4, Door 4 등 — 실제 런타임 사용처는 M4에서 다시 센다 |
| 씬 로딩 | `LevelManager`가 `SceneManager.LoadScene`으로 맵을 바꾼다. 맵 4는 마스터 씬 + 섹터 8개를 추가 로드한다. 빌드 씬은 develop 기준 맵 1~4(+섹터)뿐이다 |
| 기존 PRD의 전제 | `CloudTrampoline.md`·`DreamThread.md`·`RainbowBridge.md`: "협동 모델 = Tab 단일조작 기준, 네트워크 확장 여지만 (확정)". `RoleClueTerminal.md`: "게임 내 텍스트/음성 채팅 기능 없이도 실제 대화로 정보 교환" — 외부 통화 가정이었고, 이번 인게임 음성이 그 전제를 대체한다 |

## 5. 아키텍처 결정

### 5.1 토폴로지

- NGO **Host**(= 서버 + 클라이언트 한 프로세스). 클라이언트 2명이 Relay를 거쳐 호스트에 붙는다.
- **기믹과 퍼즐 오브젝트의 권위는 호스트 하나, 플레이어 몸은 소유자 권한(혼합 모델, D1 확정 2026-11-16).** 협동 기믹은 세 도형이 같은 물체(시소·리프트·레일카·투석기·블록) 위에서 상호작용하므로 물체는 호스트가 시뮬레이션한다. 반면 플레이어 몸까지 서버 권한으로 두면 입력 반응이 로컬에서도 약 135~160ms, 편도 50ms에서 약 250ms로 나와(§5.2 실측) 몸은 각 클라이언트가 직접 움직인다. 다른 소유자의 몸과 물체의 접촉은 이동 발판 탑승 등에서 위험이 남아 있다(R12).

### 5.2 플레이어 입력 모델 (D1 확정 — 소유자 권한 몸 + 서버 권한 기믹, 2026-11-16)

**결정:** 플레이어 몸(이동·점프·구르기 등)은 **소유 클라이언트가 로컬에서 물리를 돌리고**(`NetworkTransform` 소유자 권한) 결과 위치를 다른 사람에게 보낸다. 퍼즐 오브젝트·기믹은 **호스트가 시뮬레이션**한다. 호스트 자신의 도형도 같은 방식(자기 몸은 로컬)이다.

**근거(M1 프로토타입 실측, 2026-11-16, 로컬 2프로세스 + UDP 지연 프록시, 조건당 1회 — 경향 확인용):**

| 편도 지연 | 서버 권한: 입력→내 화면 이동/점프 | 오너 권한: 입력→내 화면 이동/점프 | 오너 권한: 입력→상대 화면에서 몸이 움직임 |
|---|---|---|---|
| 0ms | 162 / 199 ms (버퍼 0.02에서 135 / 157) | 27 / 28 ms | 70 ms |
| 25ms | 281 / 287 | 27 / 35 | 90 ms |
| 50ms | 248 / 278 | 27 / 31 | 115 ms |
| 100ms | 376 / 381 | 27 / 34 | 170 ms |

- 서버 권한은 지연 0에서도 NGO 시간 버퍼(기본 각 0.05초)와 틱 때문에 135~160ms가 바닥이라 **버퍼 조정만으로 40~50ms 이하가 불가능했다.** 소유자 권한은 내 조작이 약 27ms(물리 틱+프레임)로 지연과 무관하다.
- 상대 화면의 반응은 핑에 비례해 늘어난다(= 오너 권한의 대가). 편도 25~50ms면 90~115ms.
- 지터(화면 흔들림)는 배치모드(프레임 무제한)라서 의미 있는 값이 안 나왔다. **실제 체감·부드러움은 에디터·빌드 직접 조작으로 확인해야 한다**(미확인).
- 측정 도구·수치의 한계: `UnityTransport.SetDebugSimulatorParameters`는 NGO 2.x에서 효과가 없어 초기 측정이 무효였고, 외부 UDP 프록시(`udpdelay.py`)로 다시 쟀다. 서버 권한 쪽 값은 조건당 이동·점프 각 1회 측정이라 25ms 지점 등에서 순서가 뒤바뀐 노이즈가 있다.

**구현 규칙**
- 소유자만 `PlayerMover`·`PlayerJump`를 켜고 `Input`을 읽는다(위 4곳의 입력 분기는 유지하되 RPC 없이 로컬에서 대입). 소유자가 아닌 쪽은 몸 스크립트를 끄고 `NetworkTransform` 보간으로 받아 그린다.
- 기믹이 몸에 주는 힘·속도(바람·가속 등, `Player*Receiver`)는 소유자 쪽에서 적용되도록 서버→소유자로 전달해야 한다(M4에서 기믹별 확인).
- 몸이 물체를 미는 힘, 이동 발판 탑승, 운반처럼 몸과 서버 권한 물체가 접촉하는 경우는 **기믹별 실측으로 확인**한다(R2·R12). **탑승·운반·부착 중에는 몸의 권위를 일시적으로 서버로 넘긴다**(R12 실측 1차: 오너 측에서 카트를 따라가는 방식은 1.7~2.7m 뒤처짐). 이 구간의 입력은 오너가 서버로 보내고(RPC), 서버가 카트·좌석과 함께 시뮬레이션한다. **구현 방식은 `NetworkObject.ChangeOwnership(서버)`로 소유권을 서버에 넘기는 것이며, 2차 실측에서 어긋남이 0.12~0.18m로 줄었다**(R12).
- 대안(기각): 순수 서버 권한 — 로컬에서도 135~160ms. 클라이언트 예측·재조정 — 체감은 좋으나 규모가 커서 소유자 권한이 실패할 때만 재검토.

**(확정 §12 D10)** `NetworkManager`가 시작되지 않은 상태(= 혼자 플레이, 기존 시험 씬의 오프라인 `Tab` 모드)는 **동작이 변하지 않아야 한다.** 반대로 **멀티플레이 세션 중에는 `Tab` 전환이 동작하지 않는다**(P-02). `PlayerControlSwitcher`가 "씬에 없으면 영향 없음"으로 설계된 것과 같은 원칙이다. 네트워크 경로는 `NetworkManager.IsListening`일 때만 켠다.

## 8. Relay 비용 판단 (요청 사항)

**결론**: 개발·사내 테스트·소규모 플레이 테스트 규모에서는 **무료이거나 달러 한 자릿수**일 가능성이 높다. 다만 이는 **방당 전송량 가정**에 크게 좌우되고, 전송량은 아직 측정되지 않았다. 정식 출시 규모의 비용은 측정 후 다시 계산해야 한다.

**[공식] 입력값**: 무료 50 평균 월간 CCU / 대역폭 "3 GiB per CCU, 최대 150 GiB/월" / 초과 대역폭 $0.09(US·EU), **$0.16(아시아·호주)** / 초과 CCU $0.16.

**읽는 방식이 둘로 갈린다 — 가격 페이지 문구만으로는 확정할 수 없다 [미확인]**
- 해석 A: 무료 50 CCU에 딸린 **150 GiB가 월 총 무료량**이다.
- 해석 B: 무료 대역폭이 **실제 평균 CCU × 3 GiB**로 줄어든다(예: 평균 1 CCU면 3 GiB).

**[계산] 가정**: 방당 Relay 통과 트래픽 N KB/s(**가정값, 측정 아님**). 호스트 포함 3명 모두 CCU로 센다고 보수적으로 가정. 한국 사용자는 "아시아+호주" 요금군으로 가정(Relay 서울 권역 존재 여부는 [미확인]).

| 방당 전송량(가정) | 방 1시간당 | 방 1시간당 초과 요금 (US·EU / 아시아+호주) | 해석 A 무료(150 GiB)로 버티는 방-시간 |
|---|---|---|---|
| 20 KB/s | 70.3 MiB (≈0.069 GiB) | $0.006 / $0.011 | 약 2,185 |
| 50 KB/s | 175.8 MiB (≈0.172 GiB) | $0.015 / $0.027 | 약 874 |
| 100 KB/s | 351.6 MiB (≈0.343 GiB) | $0.031 / $0.055 | 약 437 |

- 해석 B라면 무료 대역폭이 평균 CCU에 비례해 작아진다(예: 평균 1 CCU면 3 GiB). 그만큼을 뺀 나머지에 위 표의 "방 1시간당 초과 요금"이 청구된다. 예: 50 KB/s에서 한 달 300방-시간이면 약 51.5 GiB → 아시아 요금으로 **최대 약 $8**(무료분을 하나도 못 쓴다고 본 상한).
- CCU: 3인 방 1시간 = 3 CCU-시간. 월 평균 50 CCU(= 36,000 플레이어-시간 ≈ 12,000 방-시간)까지 무료다. 이 규모를 넘기 전에는 CCU 요금이 문제되지 않는다.
- **음성은 Vivox 경유라 Relay 대역폭에 잡히지 않는다**(Vivox 가격은 별도 PCU 과금: 방 1개 = 3 PCU, 무료 5,000 PCU ≈ 동시 1,666방. 무료 구간의 다른 조건은 가격 페이지에 없다).
- **정정(2026-11-16):** 방 목록을 안 쓰는 코드 방식(§12 D2)이어도 Sessions SDK는 내부에서 Lobby를 쓰므로 Lobby 요금 항목이 **0은 아니다**. 다만 로비 데이터·하트비트는 작아 월 10 GiB 무료 안일 가능성이 높다 [미확인 — 실측 전]. Relay SDK 직접 사용 시에만 Lobby가 완전히 빠진다(§12 D3).
- **Steam 배포 시**(확정: Steam 릴레이로 교체): Relay 대신 Steam 릴레이 트랜스포트를 쓰면 Relay 요금이 사라질 수 있다. 단 SDR 이용 조건("Steam에 출시 중인 게임")과 요금은 Steamworks 문서에 명시돼 있지 않아 **출시 준비 시 Valve에 문의**가 필요하고, 앱 등록비 $100이 든다(§4.5). 다만 Facepunch 트랜스포트의 유지 상태가 확인되지 않았다(§4.4). 그래서 **Steam 전환 때 바뀌는 코드는 "세션 생성·참가" 한 곳으로 모은다**(NGO는 트랜스포트가 교체 가능한 구조). 지금 인터페이스를 미리 만들지는 않는다.

**남은 확인(비용 확정 전)**: ① 실제 방당 전송량 측정(UGS 대시보드) ② CCU·대역폭 집계 방식(해석 A/B) ③ Relay 권역에 한국에 가까운 곳이 있는지 ④ Vivox 무료 구간 조건과 초과 시 청구 방식. ④는 예산 경보 설정으로 방어한다(§10 R6).

## 9. 지켜야 할 것 (제약·원칙)

1. **Unity 6.3 업그레이드가 선행**이다. 업그레이드 계획은 별도 클론 브랜치에서 하며, 위험은 컴파일이 아니라 **물리 거동 드리프트**다(2026-09-21 사전 조사 기준 `Rigidbody.velocity` 126곳·`FindObjectOfType` 40개 파일은 경고 수준 — 그 뒤 코드가 늘었으므로 M0에서 재집계). 멀티플레이 구현과 섞지 않는다.
2. **`Time.timeScale`로 월드를 멈추지 않는다**(P-06). 모래시계의 국소 물리 조정 방식(`Hourglass.md`)이 이미 같은 이유로 선택된 선례다.
3. **무작위·타이머는 호스트에서만 돌린다**(분류 C). 각 PC가 같은 주기로 따로 돌린다는 가정을 쓰지 않는다(`FallingRock.md` §0.2).
4. **입력은 소유자 PC에서만 읽는다.** `InputGate`·`InputLocked`·ESC 메뉴는 로컬 전용이다(P-05).
5. **클라이언트에서 Rigidbody를 직접 움직이지 않는다**(소유자 권한을 택하지 않은 이상). 비권한 인스턴스는 kinematic이다(§4.1).
6. **충돌 이벤트가 필요한 기믹은 호스트에서 감지한다**(클라이언트 충돌 이벤트 미발생 — §4.1).
7. 씬 파일은 **텍스트 머지 금지**, 씬 수정은 항상 텍스트 편집·재생성 절차를 따른다(기존 저장소 규약).
8. 네트워크 변환으로 **기존 기믹 PRD의 "협동 모델: Tab 단일조작 기준, 네트워크 확장 여지만(확정)"을 갱신**해야 한다: `CloudTrampoline`·`DreamThread`·`RainbowBridge`, 그리고 `FallingRock`·`Hourglass`·`RoleClueTerminal`(1PC 시험 모드)·`ManagerSurveillance`·`Respawn`의 관련 절.
9. 사용자 입력·음성 사용 사실은 **사용자에게 고지**한다(V-08).

### 16.2 검증 완료 (코드·산술)

- §3의 코드 사실은 grep·읽기로 확인: `PlayerMover` 입력 직접 읽기(337·545행), `PlayerJump`(45행), `ViewYaw` 의존(`EffectiveInputYaw`), `Time.timeScale` 대입 위치 2곳, `freezeTime` 기본 true, `static Instance/Current` 클래스 11개, `R` 복귀가 조작 중인 도형 한 개만 대상.
- §8 표의 산술을 다시 계산해 일치 확인(예: 50 KB/s = 175.8 MiB/방-시간 = 0.172 GiB, 아시아 $0.027, 150 GiB ÷ 175.8 MiB ≈ 874방-시간, 50 평균 CCU = 36,000 플레이어-시간 = 12,000방-시간).
- 가격 수치(Relay·Lobby·Vivox)는 UGS 가격 페이지를 직접 열어 확인.
