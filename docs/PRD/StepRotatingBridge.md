# 밟기 발동 회전 다리 (Step Rotating Bridge) — PRD

> 독립 신규 기믹. 실험실 CH5 전용. 출처: Notion "요구사항명세서" —
> `[실험실 CH5] 밟기 발동 회전 다리`.
> 상태: **기획 단계 — PRD 작성만 완료, 구현 전.**
> **중요 발견**: 원본은 "기존 회전판에 상면 발동·예고·복귀를 연결한다"고 전제하지만, 기존
> `RotatingPlateSystem/RotatingPlate.cs`를 확인한 결과 **이 요구를 지원하지 않는다** — §3 참고.

## 1. 기획 의도 / 목적

발을 올리면 지형이 변한다는 규칙을 익히고, 반대편으로 빠르게 이동하게 만드는 함정이다.
회전축은 다리의 길이 방향으로 고정하고, 예고 → 단일 회전 → 역방향 복귀 → 재무장의 순서를
스크립트로 통제한다(각도·속도는 미정, 360° 전체 회전을 확정한 것은 아니다).

## 2. 동작 시나리오

1. 플레이어가 다리의 윗면을 밟으면 회전 예고가 한 번 시작된다.
2. 예고 뒤 다리가 길이 방향 축을 중심으로 회전한다. 플레이어는 전진하거나 점프해 반대편
   안전 발판으로 이동해야 한다.
3. 판에 닿았다는 사실만으로는 개인 복귀시키지 않는다 — **실제로 떨어진 플레이어만** CH5
   시작으로 복귀한다.
4. (제안 동작) 다리가 원래 자세로 돌아오고 윗면이 완전히 비면 다음 밟기를 받을 수 있다. 다른
   플레이어가 떨어져도, 그 위에 남아 타고 있는 플레이어의 판을 초기화하지 않는다.

## 3. 기존 `RotatingPlate` 재사용 가능성 확인 결과

`Assets/RotatingPlateSystem/RotatingPlate.cs`를 읽은 결과, 이 컴포넌트는 **의도적으로**
`useSpring = false`, `useMotor = false`로 고정되어 있다 — 클래스 주석에 "스프링을 쓰면 목표
각도로 되돌아가 '임의 각도 유지'가 깨진다"고 명시되어 있다. 즉 이 컴포넌트는 "플레이어가 밀어
임의 각도에서 자유롭게 멈추는" 것이 핵심 설계이고, 이번 요구인 "예고 후 지정 각도까지 정확히
회전했다가 스스로 역방향으로 복귀하는" **결정론적 스크립트 제어와 정면으로 반대되는 설계
철학**이다. 회전판에 모터/스프링을 켜는 방향으로 확장하면 기존 회전판의 "임의 각도 유지"라는
존재 이유가 깨진다.

**결론(확정 — 사용자 확인 완료, 2026-09-21)**: `RotatingPlate.cs`를 확장하지 않고, **새 폴더에
독립된 컴포넌트를 만든다.** 다만 참고할 선례가 있다 — `WindupAxleSystem/RotatingPlatform.cs`는
같은 "회전판" 이름이지만 물리 힌지가 아니라 **스크립트가 `transform`을 직접 돌리는 방식**이며,
이번 요구의 "정확한 목표 각도까지 회전 후 복귀"와 메커니즘이 훨씬 가깝다(단, 그 클래스 자체는
`WindupAxleSystem` 소유라 재사용하려면 교차 폴더 허가가 필요하다 — 이 PRD는 **동일 접근 방식을
새 폴더에서 독립적으로 다시 구현**한다).

## 4. 컴포넌트 / 스크립트 설계

예상 폴더: `Assets/StepRotatingBridgeSystem/`.

- **`StepRotatingBridge`** (kinematic `Rigidbody`, 상태 보유자) — 상태 `대기 → 예고 → 회전 →
  복귀 → 재무장 대기`를 스크립트로 통제한다. `rb.isKinematic = true`로 두고 회전은
  `Rigidbody.MoveRotation`으로 초기 자세 ↔ 목표 자세 사이를 보간한다(`WindupAxleSystem/
  RotatingPlatform`과 같은 스크립트 회전 방식 채택, HingeJoint 미사용).
- **상면 지지 검사**: `LiftSystem`이 이미 실측으로 확인한 원칙을 그대로 따른다 — **kinematic
  Rigidbody는 `OnCollisionEnter/Stay`가 오지 않으므로, 반드시 트리거 콜라이더 +
  `OnTriggerEnter/Stay`로 상면 지지를 판정한다**(`docs/PRD/Lift.md` §확정 사양,
  `LiftSystem/CLAUDE.md` 참고 선례). 판 아래/옆 접촉, 상자, 공중 스침은 발동 조건에서 제외한다.
- **낙하 판정 → 개인 복귀**: `docs/PRD/SectionRespawn.md`의 목적지 지정 개인 복귀를 재사용한다
  (목적지: "CH5 시작"). 접촉 자체가 아니라 **실제 낙하(공중 판정 + 안전 발판 이탈)**만 복귀를
  발동시킨다.
- **끼임/압착 안전 정지**: 회전/복귀 중 끼임은 `docs/PRD/PeriodicTraps.md`가 정의하는 무피해
  안전 정지 정책을 그대로 따른다(원본 문서가 명시적으로 상호 참조) — 별도 정책을 새로 만들지
  않는다.

## 5. 확정값 / 기본값

**상태 전이표** (원본 문서 그대로, 세부는 "제안 동작안"으로 표시된 부분 포함):

| 현재 | 조건 | 동작 | 다음 |
|---|---|---|---|
| 대기 | 살아 있는 도형이 상면에 지지됨 | 대상 기록, 예고 시작 1회 | 예고 |
| 예고 | 예고시간 끝 | 지정 각도까지 길이축 회전 | 회전 |
| 예고 | 도형이 내려감 | 예약된 회전을 취소하지 않는다 | 예고 유지 |
| 회전 | 설정한 끝 자세 도달 | 역방향으로 최초 자세 복귀 | 복귀 |
| 복귀 | 최초 자세 도달 | 추가 밟기 무시 | 재무장 대기 |
| 재무장 대기 | 상면에 아무 도형도 없음 | 새 발동 허용 | 대기 |

| 항목 | 확정 내용 |
|---|---|
| 회전축 | 다리 길이 방향으로 고정(로컬 축) |
| 발동 조건 | **상면 지지만** 발동. 아래/옆 접촉, 공중 스침, 상자는 발동 안 함 |
| 판 접촉 자체 | 피해가 아니다 — 실제 낙하만 개인 복귀를 유발 |
| 다중 콜라이더/동시 진입 | 동일 도형의 다중 콜라이더, 동시 두 도형 진입 모두 **하나의 주기**로 취급 |
| 예고 중 이탈 | 이미 예약된 회전은 취소되지 않는다(한 주기는 계속 진행) |
| 재무장 조건 | 상면이 완전히 비어야 다음 발동 허용 — 자동 반복 없음 |
| 타인 탑승 보호 | 한 플레이어가 추락해도 같은 판에 남아 탑승 중인 다른 플레이어의 판을 초기화하지 않는다 |
| 기존 수동 회전판 | 이 확장을 연결하지 않은 기존 `RotatingPlate`의 수동(밀어서 회전) 동작은 그대로 보존되어야 한다(회귀 없음) |

| 파라미터 | 타입 | 설명 | 상태 |
|---|---|---|---|
| 회전각 | `float`(°) | 목표 회전 각도 | 미정 |
| 회전/복귀 속도 | `float`(°/s) | | 미정 |
| 예고 시간 | `float`(s) | | 미정 |
| 판 폭/길이 | `float`(U) | | 미정 |
| 로컬 길이축/중심 | `Transform`/필드 | 참조 없으면 시작 거부 | 배치 시 지정 |

## 전체 재시작 처리

원본 문서가 명시한 표준 절차다(실험실 계열 문서 공통 5단계):

1. 새 입력·피해·예약된 동작을 중지한다.
2. 현재 시도를 종료해 이전 시도의 지연 입력을 무효화한다.
3. 대상자의 로프·탑승 등 이동 제어를 해제하고 안전한 시작 위치로 이동한다.
4. 이 챕터의 장치·문제·권한을 초기 상태로 복원한다. 다른 챕터의 진행은 보존한다.
5. 안전 복귀 완료를 확인한 후 준비 상태로 돌아간다. 개인 복귀는 본문에 지정한 항목만
   초기화한다.
