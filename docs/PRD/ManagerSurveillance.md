## 1. 기획 의도 / 목적

감시 담당이 위험을 실시간으로 동료에게 전달하고, 책·혼합 두 작업자가 조합을 완성해 추격자를
무력화하는 구조다. **CH1 추격자의 이동/모델은 재사용하되 상태(순찰/의심/추격/수면)는 CH1과
완전히 독립**이다 — 신규 전투·HP·사망 보상 시스템은 만들지 않는다.

- 감지·추격 로직, 수면/열쇠 연결, 잡힘에 의한 팀 실패 전달을 이 문서가 새로 만든다.
- 재료 조합 판정은 `docs/PRD/ReagentMixing.md`가 담당한다 — 이 시스템은 조합법을 모른다.
  사용 요청을 받아 "수락할지"만 판정한다.

## 2. 동작 시나리오

1. 참가자가 CH8 공간(시작 구역)에 들어오면 **관리자가 자동으로 순찰을 시작한다**(변경 2026-09-26 — 원문은
   필수 역할 배정 + 시작 입력). 책·혼합·감시 역할은 시작 후 각자 사물을 점유해 맡는다(`RoleClueTerminal` 역할
   슬롯 재사용). 감시 담당은 CCTV로 관리자의 방향과 상태를 관찰해 동료에게 위험을 알린다.
2. 관리자가 시야 안의 참가자를 감지거리(`D`)에서 발견하면 주황색으로 "의심"을 표시한다.
   그 대상이 절반 거리(`D/2`)까지 가까워지면 빨간색 "추격"으로 전환된다.
3. 작업자들은 조합을 완성하고(`ReagentMixing`) 관리자 **등 뒤로 몰래 다가가** 사용 거리 `U` 안에서 완성물을
   사용한다(사용 지점이 관리자에 붙어 함께 움직인다, 확정 2026-09-26).
4. 유효한 사용으로 잠든 관리자는 **챕터를 떠날 때까지 다시 깨지 않는다.** 참가자는 열쇠를
   얻고, 열쇠로 **잠긴 출구 문을 열어** 탈출한다(열쇠 문 신규 2026-09-26).
5. 잠들기 전에 한 명이라도 관리자에게 잡히면 **전원이 CH8 시작으로 복귀**한다. CH1~7의 진행은
   그대로 보존된다. 복귀 연출이 끝나면 시작 구역 안이므로 새 시도가 자동으로 시작된다(조합식도 새로 바뀐다 —
   `ReagentMixing.md` §4). 시험 모드에서는 감시·잡힘을 끄고 조합/사용 흐름만 확인할 수 있다
   (§4 "시험 감시 생략").

## 3. 컴포넌트 / 스크립트 설계

폴더: `Assets/ManagerSurveillanceSystem/`. `Assets/PathChaserSystem/`의 이동체를 참조해 재사용하되, **그 폴더의
파일은 수정하지 않는다** — CH8 전용 상태는 이 폴더 안에서 독립적으로 갖는다(교차 폴더 하드 룰 준수, CH1과
상태 공유 없음). 원안의 `ManagerFieldOfView`·`ManagerUseValidator`는 별도 파일로 만들지 않았다(아래 각 항목).

- **`ManagerAgent`** (`C8_MANAGER` + `C8_FOV`) — 순찰 경로(`C8_ROUTE`), 상태(순찰/의심/추격/수면), 이동, **시야
  판정**을 갖는다. 시야는 "바라보는 방향"을 읽는데 그 방향의 소유자가 이 컴포넌트라, `ManagerFieldOfView`로
  나누면 방향을 넘기는 배선만 늘어 합쳤다. 의심(`거리 ≤ D`)과 추격(`거리 ≤ D/2`)을 같은 판정에서 함께 평가한다.
  **`PathChaserAgent`는 수정하지 않으므로, 에이전트에 없는 것은 전부 `ManagerAgent`가 바깥에서 채운다**:
  | 필요한 동작 | 에이전트 현황 | `ManagerAgent`의 처리 |
  |---|---|---|
  | 순찰 반복 | 경로는 한 방향 1회 순회(종점에서 정지, 루프 없음) | 닫힌 경로(마지막 지점 ≈ 첫 지점)로 배치하고, `ReachedLimit`이면 `RejoinPath(0)` |
  | 바라보는 방향 | 에이전트는 회전하지 않음(위치만 이동) | FOV 기준 방향을 `ManagerAgent`가 소유 — 이동 방향으로 갱신, 의심·추격 중엔 대상 쪽으로 회전. 콜라이더 없는 모델 자식(`visual`)만 돌린다 |
  | 제자리 멈춤(의심·수면·이탈 정지·준비) | 정지 API 없음 | 의심: `MoveToOverride(현재 위치)`. 준비·수면·이탈 정지: 에이전트 컴포넌트 `enabled = false` |
  | 추격 / 마지막 확인 위치로 이동 | `MoveToOverride(target)` 매 틱 갱신 가능 | 그대로 사용(수평 추격 — 경로 높이 유지) |
  | 순찰 복귀 | `NearestPathPoint` + `RejoinPath` | CH1과 같은 방식으로 경로 최근접점 복귀 |
  | 순찰/추격 속도 차이 | `speed` 단일 필드(public) | 상태 전환 시 `speed`를 바꿔 쓴다 |
  | 전체 재시작 | `ResetToStart()` | 그대로 사용 |
  | 잡힘 판정 | 에이전트에 솔리드 콜라이더 없음, 잡힘 판정도 없음 | `ManagerCatchZone`이 별도 트리거로 판정 |
- **`ManagerCatchZone`** (`C8_CATCH`) — 관리자 자식의 트리거. 깨어 있고 잡힘이 활성인 관리자의 영역에
  살아 있는 참가자가 들어온 사건만 잡힘으로 인정한다(단순 거리/빨간색만으로는 잡히지 않는다). `OnTriggerStay`도
  받는다 — 이탈 재개·시작 직후 이미 영역 안에 있던 참가자는 Enter가 다시 오지 않는다. 기본 반경 1.2.
- **`ManagerStatusIndicator`** (`C8_STATUS`) — 순찰(초록)/의심(주황)/추격(빨강)/수면(파랑) 색을 월드에
  칠한다(MaterialPropertyBlock). 소리는 저장소에 오디오 시스템이 없어 넣지 않았다. 월드 색이라 CCTV에도 찍힌다.
- **사용 검증**(원안 `ManagerUseValidator`) — `ManagerChapterController.HandleUse`에 합쳤다. 검증 순서: 팀 실패
  미확정 → 활동 중 → 이미 수면 아님 → 정지 아님 → 관리자 깨어 있음 → 요청자 살아 있음 → 거리 ≤ U → 완성물
  보유(`ConsumeToken()` 성공). 전부 통과해야 수락하고, 수락 시 완성물 소비 + 수면 확정 + 열쇠 노출을 **한 자리에서**
  처리한다. "현재 시도" 항목은 넣지 않았다(`ReagentMixing.md` §5 — 동기 재시작이라 옛 완성물이 남지 않는다).
  "정식 관리자"는 컨트롤러가 자기 관리자의 사용 지점만 구독하는 구조로 성립한다.
- **`ManagerKeyPoint`** (`C8_KEY_POINT`) — 수면 후 노출되는 열쇠. 물리로 굴리지 않는 고정 표시물이라 "사라진
  표시를 지정점에 복원" 규칙이 필요 없다. 직접 상호작용(**Ctrl**)으로 팀 열쇠 1개(`HasKey`). 개인 복귀로 잃지
  않고, 챕터 재시작만 숨김·미획득으로 되돌린다.
- **`ManagerKeyDoor`** (신규 2026-09-26) — 열쇠로 여는 출구 문. 팀이 열쇠를 가진 상태에서 문 앞(`useRadius`
  2.5)에서 **Ctrl**을 누르면 열린다. 열쇠는 팀 권한이라 누가 주웠든 팀원 누구나 열 수 있고, 문이 하나뿐이라
  열쇠를 소모하지 않는다. 열쇠가 없으면 "열쇠가 필요합니다"만 표시. 문 몸체는 `DoorSystem/doorPhysics`를 **수정
  없이** 재사용한다(`SetPadPressed(true/false)`로 올리고 내림). 챕터 재시작 시 다시 닫힌다.
- **`ManagerCctvPanel`** (감시 화면) — `RoleSlot`(roleId `"Monitor"`)에 붙는 패널. 씬에 배치한 CCTV 카메라가
  `RenderTexture`로 그린 영상을 OnGUI 패널에 띄운다. **카메라 3대 기본**(변경 2026-09-26, 원문 "1대 이상"),
  **`←/→` 또는 `A/D`로 전환**(A/D 추가 2026-09-26 — 패널을 보는 동안 이동이 잠겨 A/D가 비어 있다). 화면을 연
  감시 담당만 볼 수 있고(`RoleSlot.CanShowTo`), 보는 동안은 이동이 잠긴다. 카메라 렌더는 패널이 열려 있을 때
  선택된 한 대만 켠다. CCTV 카메라에는 MainCamera 태그·AudioListener를 두지 않는다.
- **`ManagerChapterController`** (CH8 오케스트레이터 — `PowerMaintenanceController`와 같은 위치) —
  시작·사용 검증·수면·팀 실패·이탈 정지를 맡는다.
  - **시작 = 구역 진입 자동**(변경 2026-09-26 — 원안 "혼합대 패널 [Space] 실험 시작"과 "책·혼합·감시 3역 점유
    요건"을 폐지). 준비 상태에서 **살아 있는 참가자가 한 명이라도** 시작 구역(`startZone` Transform +
    `startZoneSize` 상자) 안에 있으면 시작하고, 그 참가자를 `SetStartOwner`("이어서 시작" 권한자)로 지정한다.
    구역은 콜라이더가 아니다 — 방 전체를 덮는 트리거는 트리거를 거르지 않는 레이캐스트(카메라 등)에 걸린다.
    "살아 있음"(복귀 연출 중 아님)을 요구하므로, 잡혀서 구역 안 시작 지점으로 복귀한 경우 연출이 끝난 뒤에야
    다시 시작된다(전체 재시작 5단계 "안전 복귀 완료 후 준비").
  - **이탈 정지**: `IParticipantPauseReceiver` 구현. 정지 중엔 관리자 이동·감지·잡힘을 모두 끈다. 재개 시 정지
    직전 상태(의심/추격 포함)로 이어간다.
  - **전원 CH8 시작 복귀(잡힘 시)** — 저장소에 팀 전체 복귀 API가 없으므로 이 컨트롤러가 기존 API를 순서대로
    부른다(모두 같은 프레임):
    1. 팀 실패 확정 플래그 → 관리자 감지·잡힘·이동 OFF(이후 들어오는 잡힘·사용 요청 무시)
    2. 참가자 전원에게 `RespawnController.RespawnPlayer(player, startPoints[i])` — **참가자마다 다른
       `SectionSafePoint`**(확정 2026-09-26). `RespawnController`는 이동 전에 같은 프레임에서 점유 검사를 해서,
       셋을 한 지점으로 동시에 보내면 전원 "비어 있음" 판정 → 같은 점에 겹친다. 순서는 `PlayerShapeIdentity.Kind`
       순(표적 동거리 판정과 같은 고정 ID). 카트/로프 탑승 해제는 `RespawnController`가 이미 처리한다
    3. `RoleAssignmentManager.ResetChapter()` — 역할 해제 + `ChapterReset` 발신 → 책 첫 페이지,
       혼합대 초기화 + 새 시도(조합식·책 본문 갱신), 열쇠 미획득·숨김, 문 닫힘, 관리자 `ResetToStart`
    4. 준비 상태 → 복귀 연출이 끝나면 구역 진입 조건으로 자동 재시작
    - 세션 정지(이탈) 상태는 `ResetChapter`가 건드리지 않으므로 그대로 유지된다.
    - 한계: 복귀 연출 중이거나 다른 기믹이 붙잡은(`IsHeld`) 참가자는 `RespawnController`가 거절해 제자리에
      남는다. CH8엔 붙잡는 기믹이 없어 두었다(코드에 `ponytail:` 주석).
- **텔레메트리**(상시, 사용자 요청 2026-09-26) — `ch8_start`·`ch8_use_accept/refuse`(사유·거리)·`ch8_caught`·
  `ch8_respawn`·`ch8_reset`·`ch8_manager_*`(상태 전이)·`ch8_catch_ignored`·`ch8_key_*`·`ch8_door_*`·`ch8_cctv_*`를
  Grafana/Loki로 보낸다. `ch8_manager_snapshot`(기본 1초, `snapshotInterval`=0이면 끔)은 참가자별 거리·시야각과
  안 보이는 사유(`ok`/`dead`/`far`/`angle`/`blocked:차폐물`)를 담아 D/F/차폐 튜닝에 쓴다.
- **그레이박스 테스트 방**: `Tools/ManagerSurveillanceSystem/Create CH8 Test Room`(열린 씬의 (300,50,0)에 방 전체를
  배선까지 생성) + `Move Players To CH8 Start`. 실제 CH8 레벨 배치는 별도 작업이다.

## 전체 재시작 처리

원본 문서가 명시한 표준 절차다(실험실 계열 문서 공통 5단계):

1. 새 입력·피해·예약된 동작을 중지한다.
2. 현재 시도를 종료해 이전 시도의 지연 입력을 무효화한다.
3. 대상자의 로프·탑승 등 이동 제어를 해제하고 안전한 시작 위치로 이동한다.
4. 이 챕터의 장치·문제·권한을 초기 상태로 복원한다. 다른 챕터의 진행은 보존한다.
5. 안전 복귀 완료를 확인한 후 준비 상태로 돌아간다. 개인 복귀는 본문에 지정한 항목만
   초기화한다.

이 기믹에서는 1~4단계가 `NotifyCaught` 한 번에 같은 프레임으로 끝나고, 5단계는 "살아 있는 참가자가 시작 구역
안"이라는 자동 시작 조건이 대신한다(복귀 연출 중인 참가자는 살아 있음에서 빠진다).
