# 측면 발사 함정 (Projectile Trap) — PRD

> 독립 신규 기믹. **CH3가 원 소유이고 CH5가 같은 기능을 별도 인스턴스로 재사용**한다(원본
> 명시: "CH3과 CH5는 같은 기능의 별도 인스턴스"). 출처: Notion "요구사항명세서" —
> `[실험실 CH3] 측면 발사 함정`.
> 상태: **기획 단계 — PRD 작성만 완료, 구현 전.**
> 스코프 메모: `docs/PRD/PeriodicTraps.md`(CH5 도끼·망치·가시)와는 **다른 시스템**이다 —
> CH5의 "함정 외다리" 시퀀스에 등장하는 측면 발사 구간은 저 문서가 아니라 이 문서가 정의하는
> 컴포넌트를 재사용한다.

## 1. 기획 의도 / 목적

점프나 로프 스윙의 출발 시점을 판단하게 만드는 위험이다. 발사구·예고·투사체 수명·접촉
신호만 새로 만들고, 실제 이동(점프/로프)과 복귀는 기존 기능에 연결한다 — 플레이어 이동
기능 자체는 변경하지 않는다.

## 2. 동작 시나리오

1. 플레이어가 안전 발판에서 발사구의 예고를 확인한다.
2. 발사체가 통로를 지나간 뒤 점프하거나 로프로 이동한다.
3. 다음 안전 발판에서 다음 발사 시점을 관찰하며 같은 방식으로 전진한다.
4. 탄은 발사한 방향으로 등속 이동하며 **플레이어를 추적하지 않는다.** CH5에서 맞으면 해당
   플레이어만 CH5 시작으로 복귀한다. **CH3에서도 탄에 맞은 즉시 CH3 시작으로 개인 복귀한다**
   (CH5와 동일 규칙, 확정 — 2026-09-21). 탄 피격과 무관한 일반 추락도 별도로 CH3 시작으로
   복귀한다(§4 표 참고, 두 트리거 모두 같은 목적지를 쓰지만 별개 사건이다).

## 3. 컴포넌트 / 스크립트 설계

예상 폴더: `Assets/ProjectileTrapSystem/`.

- **`ProjectileLauncher`** (발사구) — 고유 ID, 씬 로컬 축 기준 발사 방향. 상태
  `정지 → 시작 → 예고(W초) → 발사 1회 → 휴식(R초) → 예고`를 반복한다. 시작 입력을 다시
  받아도 이미 도는 주기를 중첩시키지 않는다.
- **`ProjectileWarning`** (발사구당 1개) — 예고 시각 표시. 준비 상태에서만 표시, 무피해.
- **`Projectile`** (발사마다 생성) — 발사 시 정해진 방향으로 등속 이동, 표적 추적 없음.
  발사 ID·챕터·시도 정보를 부여받는다. **벽 충돌 / 유효 대상 접촉 / 수명 `L` 중 가장 먼저
  만족하는 조건에서 소멸**한다. 동일 탄이 다중 콜라이더에 닿아도 대상당 1회만 접촉 처리하고,
  소멸 후에는 재피해를 주지 않는다.
- **개인 복귀 연결**: `docs/PRD/SectionRespawn.md`의 목적지 지정 개인 복귀를 재사용한다.
  CH3 인스턴스는 목적지 `"CH3 시작"`(확정 — 2026-09-21), CH5 인스턴스는 목적지 `"CH5 시작"`
  (확정).

## 전체 재시작 처리

원본 문서가 명시한 표준 절차다(실험실 계열 문서 공통 5단계):

1. 새 입력·피해·예약된 동작을 중지한다.
2. 현재 시도를 종료해 이전 시도의 지연 입력을 무효화한다.
3. 대상자의 로프·탑승 등 이동 제어를 해제하고 안전한 시작 위치로 이동한다.
4. 이 챕터의 장치·문제·권한을 초기 상태로 복원한다. 다른 챕터의 진행은 보존한다.
5. 안전 복귀 완료를 확인한 후 준비 상태로 돌아간다. 개인 복귀는 본문에 지정한 항목만
   초기화한다.
