# 구간별 개인 복귀·피격 알림 (Section Respawn) — PRD

> 독립 신규 기믹이 아니라 **기존 `RespawnSystem`의 확장**. 실험실 CH1·3·4·5·6·7·8이 공용으로
> 참조하는 두 번째 공유 인프라(`docs/PRD/RoleClueTerminal.md`가 CH7·8의 첫 번째 공유
> 인프라였다면, 이건 위험 구간이 있는 모든 챕터의 공유 인프라). 출처: Notion "요구사항명세서" —
> `[실험실 CH3~4] 구간별 개인 복귀·피격 알림`.
> 상태: **기획 단계 — PRD 작성만 완료, 구현 전.** CH1 경로 추격자, CH3 측면 발사 함정,
> CH4 조준 예고 보안 레이저, CH5 물리 함정 등 후속 PRD가 이 문서의 확장 지점을 전제로
> 이어서 작성될 예정이다.

## 1. 기획 의도 / 목적

개인의 실수를 **개인의 재도전**으로만 연결하고 동료의 진행은 건드리지 않는다. 새 HP·부활
체계를 만들지 않고, 기존 `RespawnSystem`(`docs/PRD/Respawn.md`)의 순간이동·조작 해제·연출
기능을 그대로 재사용한다.

**핵심 설계 충돌과 그 해소**: 기존 `RespawnSystem`은 2026-07-31에 "체크포인트는 도형별이
아니라 셋이 공유하는 마지막 하나"로 확정했다(팀 단위 실패라는 전제, `Respawn.md` §5). 그런데
이번 요구는 정반대다 — **같은 챕터 안에서도 어느 위험에 맞았는지에 따라 서로 다른 목적지**로
보내야 한다(예: CH4는 "낙석 시작점"과 "레이저 시작점"이 별개, CH1은 벽 파괴 전/후 안전점이
별개). 이는 "마지막으로 밟은 공용 체크포인트 하나"라는 기존 모델로는 표현할 수 없다.

해소 방식: 자동(장외 3초)·수동(`R`) 트리거는 기존 공용 체크포인트 모델을 **그대로 유지**한다
(맵 전역 안전망이라는 역할은 바뀌지 않는다). 이번 확장은 **제3의 트리거 경로** — 이미
`RespawnController.RespawnPlayer(GameObject)`가 `FallingRockSystem` 배선에서 쓰는 "특정
피해 사건이 특정 플레이어 하나를 지목해 복귀시키는" 경로를 그대로 넓혀서, **호출자가 목적지를
지정할 수 있게** 만든다. 지금은 이 경로도 결국 공용 체크포인트로 가지만(그게 우연히 구간
진입부에 있어서 맞아떨어질 뿐), 여러 목적지가 필요해지는 순간 이 가정이 깨진다.

## 2. 동작 시나리오

1. CH4 낙석 구간에서 첫 번째 유효 피격을 받으면 그 플레이어 화면에만 "한 번 더 맞으면 낙석
   구간 처음으로 돌아갑니다" 경고가 뜬다.
2. 같은 플레이어가 같은 구간에서 두 번째 유효 피격을 받으면 그 플레이어만 낙석 구간 시작으로
   복귀한다. 복귀 완료 후 그 구간의 피격 횟수는 0으로 리셋된다.
3. CH4 레이저는 카운터 없이 1회 피격으로 즉시 복귀하며, 목적지는 낙석 시작점과 다른 "레이저
   구간 시작점"이다 — 같은 챕터 안에 있어도 원인에 따라 목적지가 다르다.
4. 복귀 처리는 대상의 로프·탑승 등 이동 제어를 해제하고 안전한 위치에서 조작을 돌려준다.
   동료의 위치와 진행 중인 공용 퍼즐 상태는 그대로 유지된다.
5. **예외**: CH8 관리자에게 잡히는 것은 개인 복귀가 아니라 **CH8 팀 전체 재시작**으로 연결한다
   (§4 표의 마지막 행). 이 문서가 정의하는 "개인 복귀" 경로를 타지 않는다.

## 3. 컴포넌트 / 스크립트 설계

`Assets/RespawnSystem/` 확장(새 파일 추가, 소유 폴더 동일이라 교차 폴더 이슈 없음). 각
챕터의 위험 장치(낙석·레이저·함정 등)는 자기 폴더에 남고, 이 시스템이 제공하는 공용 API를
호출하는 방향은 `FallingRockSpawner → RespawnController` 선례와 동일하게 유지한다.

- **`SectionSafePoint`** (신규, `RespawnSystem` 소유) — 이름 있는 개인 복귀 목적지 하나.
  `sectionId`(예: `"CH4_FallingRock"`, `"CH4_Laser"`, `"CH1_SafePre"`)와 순간이동 좌표를 갖는다.
  기존 `RespawnZone`과 달리 "밟으면 저장"이 아니라 **레벨 디자이너가 직접 배치하고 참조하는
  고정 지점**이다 — 여러 개가 동시에 존재해도 서로 덮어쓰지 않는다.
- **`RespawnController` 확장(기존 파일에 오버로드 추가)** — 기존
  `RespawnPlayer(GameObject player)`(공용 체크포인트로 보냄)에 더해
  `RespawnPlayer(GameObject player, SectionSafePoint destination)` 오버로드를 추가한다.
  목적지 조회만 다르고 나머지(조작 차단, 로프/탑승 해제, 중력 상태 적용, 페이드 연출, 붙잡힘
  시 미루기/거절 판정)는 기존 경로를 100% 재사용한다 — **연출·안전 로직을 복제하지 않는다.**
- **`SectionHitCounter`** (신규, `RespawnSystem` 소유) — `FallingRockSpawner`가 이미 구현한
  "참가자×구간 키로 피격 0/1 집계, 임계 도달 시 이벤트 발화, 복귀 성공 후 0으로 리셋" 패턴을
  일반화한 재사용 컴포넌트. 임계값을 1로 두면 즉시 복귀(레이저)와 동일해지므로 별도 분기 없이
  카운터 하나로 두 케이스(낙석의 "2회 중 1회 경고", 레이저의 "즉시 복귀")를 표현한다.
  `hitsBeforeRespawn` 필드, `UnityEvent<GameObject>`(경고 표시용, 임계 1회 전)와
  `UnityEvent<GameObject>`(복귀 발화용, 임계 도달) 두 채널을 갖는다 — 기존
  `FallingRockSpawner.OnHitThresholdExceeded`와 같은 계약.
- 각 위험 장치(CH1 추격자, CH3 발사구, CH4 레이저, CH5 함정 등)는 자기 폴더에서
  `SectionHitCounter`를 참조해 피격을 보고하고, 카운터의 복귀 이벤트를
  `RespawnController.RespawnPlayer(player, destination)`에 인스펙터로 꽂는다 — 지금
  `Tools > Respawn > Wire Falling Rock Hits`가 하는 것과 같은 배선 방식을 그대로 따른다.

## 4. 확정값 / 기본값

원인별 목적지·초기화 범위는 원본 문서의 확정 사항이다. "검토 중" 표시는 원본이 명시한 미결정
항목이며 이 PRD에서 임의로 확정하지 않았다.

| 원인 | 대상/목적지 | 초기화/보존 | 상태 |
|---|---|---|---|
| CH1 잡힘 | 해당 도형 / 벽 파괴 전·후 안전점(`SAFE_PRE`/`SAFE_POST`) | 동료·벽·카트 상태 보존 | 확정 |
| CH3 추락 | 해당 도형 / CH3 시작 | 자기 구속 해제 | 확정 |
| CH3 직접 탄 피격 | 해당 도형 / CH3 시작 | 동료·탄/주기 보존 | 확정(2026-09-21) |
| CH4 낙석 2회 | 해당 도형 / 낙석 구간 시작 | 자기 낙석 횟수 0으로 리셋 | 확정 |
| CH4 레이저 1회 | 해당 도형 / 레이저 구간 시작 | 동료·자기 낙석 횟수는 보존(별개 카운터) | 확정 |
| CH5 함정/추락 | 해당 도형 / CH5 시작 | 함정 주기·동료 상태 유지 | 확정 |
| CH6 추락 | 해당 도형 / CH6 시작 | 전이(포탈) 구속 해제 | **검토 중(미결정)** |
| CH7/8 개인 낙하 | 해당 도형 / 챕터 안전점 | 문항·혼합 진행·키 등 공용 상태는 보존 | **검토 중(미결정)** |
| CH8 관리자 잡힘 | **개인 복귀 아님** — 전원 / CH8 시작 | 관리자 잡힘에 의한 팀 전체 재시작. 이 문서의 개인 경로를 쓰지 않는다 | 확정 |

| 항목 | 확정 내용 |
|---|---|
| 피격 집계 키 | (시도, 참가자, 구간) — 스포너/발사구가 여러 개라도 같은 구간이면 합산 |
| 같은 판정 묶음 처리 | 같은 순간에 겹치는 여러 피해 판정(예: 낙석 여러 개 동시 접촉)은 1회로 합친다. 서로 다른 시점(판정 묶음)의 피격은 각각 센다 |
| 수동 복귀와의 상호작용 | 참가자가 수동(`R`)이나 다른 경로로 실제 해당 구간 시작점에 복귀하면 그 구간 카운터도 0이 된다. 다른 목적지로 복귀한 경우 카운터는 보존 |
| 복귀 순서 | (1) 대상·구간·시도 유효성 확인·중복 요청 병합 → (2) 피해 사건 기준으로 목적지 확정(동료 진행 상황과 무관) → (3) 입력·추가 피해 잠금, 로프/탑승/외부 이동 해제 → (4) 안전점 점유 검사(겹치면 사전 배치된 보조 지점 중 첫 가용 지점 사용, 모두 막히면 강제로 벽 안에 넣지 않고 오류 표시) → (5) 기존 순간이동 실행, 잔여 속도 정리, 목적지 중력 상태 적용 → (6) 완료 후 카운터/복귀중 플래그 해제·조작 복원 |
| 안전점 다중화 | 각 `SectionSafePoint`는 겹침 회피용 보조 지점을 여러 개 가질 수 있다(레벨 배치 사항, 코드가 자동 생성하지 않음) |
| 붙잡힌 참가자 | 기존 `RespawnSystem`과 동일한 정책 재사용 — 자동 트리거는 미루고(타이머 유지), 이 경로의 명시적 호출(위험 장치가 직접 지목)은 거절하지 않고 즉시 처리(위험 피격은 "지금 확정된 사건"이라 `R`과 같은 성격) |
| 새 HP/부활 체계 | 만들지 않는다(확정 — 원본 요구) |

  낙석 코드는 건드리지 않고, 신규 장치부터 공용화)를 기본 가정으로 둔다 — `FallingRockSystem`
  폴더는 이미 "완료" 상태이고 불필요한 재작업을 만들지 않기 위함이다.

## 전체 재시작 처리

원본 문서가 명시한 표준 절차다(이 저장소의 "실험실" 계열 문서 대부분이 공유하는 동일한
5단계 — 다른 PRD에서 재정의하지 않고 그대로 참조한다):

1. 새 입력·피해·예약된 동작을 중지한다.
2. 현재 시도를 종료해 이전 시도의 지연 입력을 무효화한다.
3. 대상자의 로프·탑승 등 이동 제어를 해제하고 안전한 시작 위치로 이동한다.
4. 이 챕터의 장치·문제·권한을 초기 상태로 복원한다. 다른 챕터의 진행은 보존한다.
5. 안전 복귀 완료를 확인한 후 준비 상태로 돌아간다. 개인 복귀는 본문에 지정한 항목만
   초기화한다.
