## 1. 기획 의도 / 목적

CH2 격리 퍼즐을 **제한시간 안에** 끝낸 팀이 CH4 지름길 문을 통과하면, 물리적으로 긴 CH3 통로를
새로 만들지 않고 **CH4 시작으로 복귀할 권리**를 얻는다.

- 문 뒤의 CH2 쪽 구역(**A**)은 체크포인트를 **저장하는 스위치**일 뿐이다. 실제 안전 착지점과
  깃발은 CH4 시작의 기존 `RespawnZone`(**B**)에 있다.
- 복귀 입력은 기존 수동 복귀(`R`)를 그대로 쓴다. 실패한 팀은 이 장치로 CH4에 갈 수 없다.
- 새 순간이동·복귀 연출 코드는 만들지 않는다. B를 팀 공유 체크포인트로 저장하는 것까지만 한다.

## 2. 현재 상태 (코드 확인, 2026-10-04)

| 항목 | 확인 내용 |
|---|---|
| 체크포인트 | `RespawnController`가 씬에 하나. 도형 셋이 공유하는 `currentZone` 하나만 유지 |
| 저장 경로 | `RespawnZone.OnTriggerEnter` → `RespawnController.SetCheckpoint(zone)` → `StoreCheckpoint` |
| 중복 방지 | `claimed` 집합: **한 번 잡은 구역은 다시 활성화되지 않는다**(되감기 방지). 그러나 **아직 안 밟은 과거 구역**이 현재 체크포인트를 덮어쓰는 것은 막지 못한다 |
| 구역 식별 | `RespawnZone`에 **ID도 진행 순서도 없다** |
| 복귀 | `R`은 현재 조작 중인 도형만 `TryRespawn`. 낙하·킬 라인도 같은 체크포인트로 간다 |
| 재시작 | 체크포인트를 되돌리거나 비우는 기능이 **없다** |
| 복귀 겹침 | `RespawnZone` 복귀에는 점유 검사가 없다(점유 검사는 `SectionSafePoint` 경로에만 있다). 세 도형이 같은 중앙점으로 복귀한다 |
| CH2 성공 신호 | `IsolationRescueController.onSuccess` — **제한시간 안에 최종 해제가 성공했을 때만** 발신(`TryRelease`가 마감을 먼저 확인). 실패 쪽은 `onTimedOut`·`onAborted`, 재시작은 `FullRestart()`/`onRestarted` |

## 3. 컴포넌트 / 스크립트 설계

### 3.1 구성품 (씬)

- **A: 성공 출구 뒤 감지 구역.** 성공으로 열린 문을 지나야만 몸이 들어갈 수 있는 위치에 둔다.
  A 자체에는 복귀 깃발이나 착지 지점을 두지 않는다.
  - 진입 판정은 **`ZoneEntryDetector`(`새 진입마다` 모드) 재사용**(확정). "도형 하나의 여러
    콜라이더는 한 번의 진입으로 합친다"는 요구가 `ZoneEntry.md` §4와 같다.
- **B: CH4 시작의 기존 `RespawnZone`.** 안전한 바닥 위에 두고, 세 도형이 복귀해도 벽·바닥·서로의
  몸체에 끼지 않는 공간을 확보한다. B의 기존 깃발·낙하 시작점·바닥 계산을 그대로 쓴다.

### 3.2 새 컴포넌트 `RemoteCheckpointGate` (A에 부착, 폴더 `Assets/RemoteCheckpointSystem/`)

- 필드: `targetCheckpointId`(string), 잠금 상태(**초기값 잠금**).
- `SetUnlocked(bool)` — 외부 이벤트로 해금하는 진입점. CH2의 `onSuccess`를 `SetUnlocked(true)`에,
  `onTimedOut`·`onAborted`·`onRestarted`를 `SetUnlocked(false)`에 인스펙터로 연결한다.
  문이 눈에 보이게 열린 것만으로 성공을 추측하지 않고 **퍼즐 결과를 입력으로 받는다.**
- 출력: `OnCheckpointStored`(`UnityEvent`) — 저장에 **성공한 경우에만** 발신. 문 뒤의
  "R을 누르면 CH4 시작으로 이동" 안내 오브젝트를 이 이벤트로 켠다(문구·표시 방식은 맵 담당).
  저장에 실패하면 안내를 띄우지 않는다.
- 동작 순서 (유효 진입 한 번마다):
  1. 잠겨 있으면 무시한다.
  2. 현재 로드된 모든 씬에서 `checkpointId`가 `targetCheckpointId`와 같은 **활성** `RespawnZone`을
     찾는다. **정확히 하나**가 아니면(없음/둘 이상) 저장하지 않는다. 임의의 "첫 번째 B"를
     고르지 않는다. 경고에는 A 이름과 대상 ID를 남긴다.
  3. 아직 B가 로드되지 않았거나 ID가 없거나 둘이면 **"이미 획득한 체크포인트"로 기록하지
     않는다.** B가 나중에 로드된 뒤 A에 다시 들어오면 정상적으로 다시 시도한다.
  4. 컨트롤러의 저장 경로(`SetCheckpoint`)를 호출한다. **B 객체 자체**를 저장하며 A의 위치나
     CH2 문 좌표를 낙하 지점으로 쓰지 않는다.
  5. 저장에 성공한 **최초 한 번만** 체크포인트 저장·깃발 변경·안내를 처리한다. 같은 B에 A가 여러
     번 들어오거나 세 도형이 차례로 들어와도 반복하지 않는다.
- A 진입이 개인 피격 횟수나 CH2 퍼즐 답·타이머를 초기화하지 않는다.

### 3.3 `RespawnSystem` 변경 (이 PRD 범위)

구현은 `RespawnZone`·`RespawnController`를 수정하므로 **착수 전 사용자 허가를 확인한다**
(저장소 하드 룰).

- `RespawnZone`에 추가: `checkpointId`(string, 씬 전체에서 중복 금지), 진행 순서
  `progressOrder`(int)와 순서 사용 여부.
- `StoreCheckpoint`에 순서 비교 추가: 새 구역과 현재 구역이 **모두 순서를 쓰면** 새 구역의
  순서가 더 클 때만 수락한다. 그래서 B가 활성인 뒤 **아직 안 밟은 과거 CH2 구역**을 처음
  밟아도 B가 유지된다.
- **순서를 쓰지 않는 구역끼리의 기존 규칙은 바꾸지 않는다.** 이 확장을 연결하지 않은 기존 맵의
  저장 동작은 그대로다.
- 순서가 빠진 구역이 순서를 쓰는 활성 체크포인트를 덮어쓰려 하면 덮어쓰지 않고 **배치 오류**를
  남긴다. 같은 진행 구간에서 순서가 중복되어 어느 쪽이 뒤인지 모호한 배치도 배치 오류다.
- 재시작용 진입점 추가(§5, 확정): 팀 체크포인트를 **지정 구역으로 되돌리고** 지정한 구역들의
  잡음 기록을 지운다.

## 4. 성공 문 통과부터 R 입력까지

1. CH2 퍼즐이 제한시간 안에 성공하면 `onSuccess`가 A를 해금하고 CH4행 문이 열린다.
2. 한 도형이 문 뒤 A에 처음 들어간다. (같은 도형의 여러 콜라이더는 한 번으로 합친다.)
3. §3.2의 순서대로 B를 찾아 저장한다. 이전 깃발은 지나온 상태(흰색), B 깃발은 활성(초록)이 된다.
4. 저장에 성공한 다음에만 안내가 켜진다.
5. `R`을 누른 **그 도형만** 기존 수동 복귀 연출을 거쳐 B의 안전 지점으로 이동한다. 다른 도형을
   그 순간 강제로 끌고 가지 않는다. 단 체크포인트는 공유이므로 **이후 다른 도형이 `R`을 누르거나
   낙하하면 그 도형도 B로 간다.** CH2 안에서 낙하해도 B로 간다는 뜻이다.

## 5. 실패·복귀·전체 재시작

- **저장 실패 사유** (대상 ID 누락·중복, B 씬 미로드·B 비활성, CH2 성공 신호 부재, 진행 역방향):
  기존 팀 체크포인트와 깃발을 그대로 둔다. 경고에 A 이름과 대상 ID를 남겨 맵 담당이 배선을 찾을
  수 있게 한다.
- **세 도형 모두 B로 복귀할 수 있어야 한다.** 안전 착지 범위를 실제 세 도형 크기로 확인한다.
  동시 복귀 요청이 서로 겹친 채 조작 불능이 되어서는 안 된다. 현재 `RespawnZone` 복귀에는 점유
  검사가 없어 같은 중앙점으로 모이므로(§2), 분산 방식은 **구현 시 실측으로 정한다**(기존 팀 복귀
  구조에 맞추되 결과는 동일해야 한다).
- **챕터 전체 재시작 (확정: 지정 구역으로 되돌림).** A 성공 상태(잠금)와 B 활성 상태를 함께
  초기화한다. `RespawnController`가 팀 체크포인트를 **지정 구역(예: CH2 시작)으로 되돌리고**,
  지정한 구역들의 잡음 기록을 지운다. 되돌릴 구역과 지울 구역 목록의 배선은 맵 담당이 한다.
  같은 플레이 시도 안의 개인 복귀는 B 활성 상태를 유지한다.
- **B가 활성인 채 필수 CH4 씬을 언로드하는 배치는 허용하지 않는다.**

## 6. 맵에서 조립하는 순서

1. CH4 시작에 B를 배치하고 안전한 낙하·바닥 위치를 세 도형으로 시험한다. B에 유일 ID와 맵4 진행
   순서를 준다.
2. CH2의 모든 기존 체크포인트에 B보다 **앞선** 순서를 준다. 같은 진행 구간에서 순서가 중복되지
   않게 한다.
3. 성공 문 뒤에 A를 배치하고 B ID와 CH2 성공·실패·재시작 신호를 연결한다. 실패 출구에서는 A에
   접근할 수 없게 한다.
4. A 뒤에 `R` 안내를 두되 `OnCheckpointStored` 뒤에만 보이게 한다. A를 지난 뒤 `R`을 누르기
   전까지 도형이 안전하게 서 있을 자리를 남긴다.
5. 각 도형의 `R`·낙하 복귀, B 활성 후 CH2로 역주행, B 미로드·ID 중복을 시험한다. 대상 없는 기존
   `RespawnZone`의 자기 자신 저장도 회귀 시험한다.

## 9. 구현 요약과 시험 씬 (2026-10-04)

**`RespawnSystem` 변경(허가받음, 필요한 부분만)**
- `RespawnZone`: `checkpointId`·`useProgressOrder`·`progressOrder` 필드만 추가.
- `RespawnController`: `TryStoreCheckpoint`(저장 성공 여부 반환), `PassesProgressOrder`, `RestartCheckpoint(returnTo, clearZones)` 추가.
  `StoreCheckpoint`는 bool을 반환한다. 순서 거절은 `claimed`에 넣지 않는다. 기존 `SetCheckpoint`·`RespawnPlayer` 시그니처는 그대로다.
- `RestartCheckpoint`: 현재 체크포인트 깃발을 내리고 `clearZones`의 잡음 기록·깃발을 지운 뒤 `returnTo`를 팀 체크포인트로 저장한다(순서 비교 없음). `returnTo`가 null이면 체크포인트 없음 상태.

**`RemoteCheckpointGate`**: `ZoneEntryDetector`(새 진입마다) 필수, Awake에서 코드로 `OnValidEntry`에 연결.
`SetUnlocked(bool)`·`RestartChapter()`·`OnCheckpointStored`. 저장 실패 시 `stored`를 세우지 않아 재시도된다.

**시험 씬 `RemoteCheckpointTest`** — `Tools > RemoteCheckpointSystem > Create Test Scene`으로 다시 만들 수 있다(기존 씬은 건드리지 않음).
+X 방향 일직선: `CH2_Start`(순서10) → `CH2_Mid`(20) → `CH2_Back`(5, 안 밟은 과거 구역) → **A**(x=0, 폭 20 전체) →
`Legacy_NoOrder`(순서 없음) → `B_CH4Start`(순서100, id `CH4_Start`). 세 도형은 `CH2_Start`에서 시작한다.
화면 패널/키로 CH2 신호를 흉내 낸다: **F1** 성공(해금) / **F2** 실패(잠금) / **F3** 챕터 재시작.

## 전체 재시작 처리

실험실 계열 문서 공통 5단계(새 입력·피해·예약 동작 중지 → 현재 시도 종료 → 이동 제어 해제와
안전 위치 이동 → 이 챕터의 장치·권한 초기화, 다른 챕터 진행 보존 → 안전 복귀 확인 후 준비
상태)를 따른다. 이 장치에서는 A 잠금과 B 활성 해제, 팀 체크포인트 복귀가 4단계에 해당한다(§5).
