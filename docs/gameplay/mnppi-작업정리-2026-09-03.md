# 1. 마찰 스티커 (Friction Sticker)

`Assets/FrictionStickerSystem/` · PR #70(신설) + #76(조준 근접화) · 이슈 #69

## 무엇인가

플레이어가 표면에 스티커를 붙였다 떼어 **마찰력을 바꾼다.**

| 종류 | 효과 | 조준점 색 |
|---|---|---|
| 미끄럼 (Slip) | 마찰 감소 → 경사 가속, 블록 운반, 레일카 가속 | 파랑 |
| 벨크로 (Velcro) | 마찰 증가 → 경사 정지, 블록 고정, 레일카 제동 | 주황 |

## 조작 (근접 방식 — 카메라 조준 안 함)

- `StickerSurface` 표면에 **4칸 안**으로 다가가면 그 표면 위에 색깔 조준점(구)이 뜬다.
- **`V`**: 조준점 색대로 부착. 다른 종류가 붙어 있으면 교체(회수 먼저 안 해도 됨). 같은 종류면(조준점 흰색) 회수.
- **`Q`**: 미끄럼 ↔ 벨크로 선택 전환.
- (`F`·`G`는 꿈의 실타래가 사용 중이라 `V`.)

## 동작 원리

| 파일 | 역할 |
|---|---|
| `StickerSurface.cs` | 부착 허용 표면 마커. 허용 종류 + "표면당 1개" 슬롯(`Current`). |
| `FrictionSticker.cs` | 런타임 생성. 대상 콜라이더의 `sharedMaterial`을 **인스턴스 `PhysicMaterial`로 교체**, 회수/파괴 시 원복. 종류 색 데칼. |
| `FrictionStickerSettings.cs` | 종류별 마찰값·조합방식·색·크기 튜닝. |
| `PlayerStickerCarrier.cs` | 플레이어에 런타임 `AddComponent`. 근접 타겟팅 + 입력 + 조준점. |
| `FrictionStickerController.cs` | 씬 진입점. `RuntimeInitializeOnLoad` 자동 생성. 튜닝값 노출. |
| `Editor/…MenuItem.cs`, `…TestPlaygroundMenuItem.cs` | 생성 메뉴 + 30° 경사 테스트 리그. |

**마찰 차이가 확연한 원리**: 접촉 마찰은 두 재질 중 우선순위 높은 `frictionCombine`으로 정해진다(`Maximum > Multiply > Minimum > Average`). 플레이어 재질은 `Average`라 —
- 미끄럼 = `Multiply` → 플레이어마찰 × 0.05 (플레이어 `Average`를 이겨 확실히 미끄럼)
- 벨크로 = `Maximum` → max(플레이어마찰, 1.2) (확실히 잡힘)

## 플레이테스트 결과

- 정육면체: 미끄럼 경사 → 못 올라감 / 벨크로 → 쑥쑥 그립. **확연히 다름.**
- 구: 미끄럼 → 빠른 활강 / 벨크로 → "걸리는 느낌"으로 느려짐 (구는 굴러서 완전 정지는 안 됨 — 물리적으로 정상. "정지"는 블록·미끄러지는 물체 대상).
- 부착/교체/회수, `Q` 전환, 조준점 색, 마찰 원복 모두 동작. 에러 없음.
- **완료조건 "같은 경사면에서 일반/미끄럼/벨크로 결과가 확연히 다르다" 만족.**

## 미해결 / 후속

- **중첩 규칙 미확정** (명세서에 "정한다"만 있고 값 없음) → 현재 "표면당 1개, 새로 붙이면 교체"로 임시 구현. `StickerSurface.Current` + `FrictionSticker.Attach`만 바꾸면 규칙 변경 가능.
- 시소·레일카는 아직 코드에 없음. 스티커는 대상 독립적이라 그 시스템 생기면 `StickerSurface`만 붙이면 됨.

# 2. 자유 회전 장난감 판 (Rotating Plate)

`Assets/RotatingPlateSystem/` · PR #72(신설) · 이슈 #71

## 무엇인가

플레이어가 **밀거나 부딪혀** 임의 각도로 돌리고, 그 각도에서 멈춰 **지형(경사로·다리·임시벽·발사대)처럼** 쓰는 회전판.

## 동작 원리 — HingeJoint (모터·스프링 없음)

- **스프링 없음** → 목표 각도로 안 돌아옴 → `0°`·`90°` 스냅 없이 **민 각도 그대로 유지**.
- **모터 없음** → 강제 회전 안 함 → 플레이어 밀기·충돌로만 회전.
- 회전은 전부 PhysX → 밀기·쐐기/블록 정지 모두 **코드 없음.**

| Inspector 필드 | 매핑 |
|---|---|
| `rotationAxis` | `HingeJoint.axis` (기본 `(1,0,0)` 시소식) |
| `useLimits` + `minAngle`/`maxAngle` | `HingeJoint.limits` — 범위 제한(스냅 아님) |
| `angularResistance` | `Rigidbody.angularDrag` |
| `maxAngularSpeedDeg` | `Rigidbody.maxAngularVelocity` |
| `plateUseGravity` | 기본 off = 민 각도 유지 / on = 무게로 처짐 |

**태엽 축 연동 스텁**: `ApplyDriveTorque(float)` + `HingeAxisWorld` 노출. 태엽 동력 회전은 `태엽 축` 기믹(송원석, 미착수) 나오면 이 둘만 호출하면 배선 끝.

**와이어 앵커**: 메뉴가 판 자식으로 `ThreadAnchor`(DreamThreadSystem) 마커 2개 배선. 진자 피벗이 연결 시점 월드 좌표 스냅샷이라 판이 돌아도 물리 안 터짐(피벗 판 추종은 후속).

## 플레이테스트 결과

- 판 끝을 밀면 힌지 축 기준 시소처럼 회전. 밀기 멈추면 **그 각도 유지**(복귀·스냅 없음). 여러 각도 확인.
- 판 밑에 정육면체 밀어넣으면 **회전이 물리로 막힘.**
- `Use Limits` + Min/Max Angle → 범위 제한 동작.
- 에러 없음 (`Setting angular velocity of a kinematic body` 경고도 안 뜸).
- **완료조건 "서로 다른 임의 각도에서 실제 발판으로 사용 가능" 만족.**

## 미해결 / 후속

- **태엽 동력 회전** — `태엽 축`(송원석) 나오면 `ApplyDriveTorque()` 배선.
- **정사면체 쐐기로 회전 정지** — `세모 쐐기 고정`(송원석) 나오면 연동 실측. 현재는 임의 콜라이더가 물리로 막는 것으로 성립.
- 와이어 피벗 판 추종 — `DreamThreadController` 수정(교차 폴더) 필요, 별도 논의.

# 3. 딱딱 블록 (Snap Block)

`Assets/SnapBlockSystem/` · PR #74(신설) + #76(조준 근접화) · 이슈 #73

## 무엇인가

블록끼리 **면을 맞대 강접합**해서 계단·다리·경사로·추 같은 구조물을 즉석에서 만드는 기믹. 결합·해제 가능.

## 조작 (근접 방식)

- `SnapBlock` **4칸 안**으로 다가가면 그 블록이 대상.
- 다른 블록의 면과 **거리(0.6) + 각도(20°, 법선 정반대)** 조건을 통과하는 가장 가까운 면 쌍에 **초록 구 하이라이트** 2개.
- **`E`**: 결합 없으면 → 후보와 결합(자동 정렬). 결합 있으면 → 그 블록만 구조물에서 분리.

## 동작 원리

| 파일 | 역할 |
|---|---|
| `SnapBlock.cs` | 블록 하나. 박스 6면 bounds 계산. `Weld`/`DetachFrom`/`DetachAll` + 양쪽 대칭 연결 그래프. |
| `SnapBlockController.cs` | 씬 진입점. `RuntimeInitializeOnLoad` 자동 생성. 근접 타겟팅 + 후보 탐색 + 하이라이트. |
| `Editor/SnapBlockMenuItem.cs` | 블록/컨트롤러 생성 메뉴. |

**결합 = all-locked ConfigurableJoint + projection** (`FixedJoint` 아님). 전 축 `Locked` + `projectionMode = PositionAndRotation`으로 조인트가 규정 자세에서 벗어나면 하드 복귀 → **Joint 폭주 억제.**

**폭주 억제 3종**: ① 결합 직전 대상 블록을 상대 면에 정확히 맞춘 자세로 스냅(초기 침투 제거) ② `solverIterations` 20 + `ContinuousDynamic` + `Interpolate` ③ 결합 순간 양쪽 속도 0. `jointBreakForce` Inspector 노출(기본 무한).

**구조물 크기 제한**: `maxBlocksPerStructure`(기본 12). 결합 전 BFS로 세어 초과 시 거부 + 로그.

## 플레이테스트 결과

- 블록 밀어붙이면 초록 구 표시 → `E` → 정렬되며 결합.
- 3개로 계단/벽 조립 → **폭주·과진동 없이 안정.**
- 결합된 블록 근처 `E` → 그 블록만 분리.
- `Max Blocks Per Structure` 3으로 낮추고 4개째 → 거부 + 로그.
- 에러 없음. **완료조건 "결합 후 구조물이 자연스럽게 움직인다" 방향 만족.**

## 미해결 / 후속

- **Joint 폭주는 완화지 100% 보장 아님.** 블록 많거나 무거운 도형이 세게 부딪히면 흔들릴 수 있음 → `solverIterations`/`projectionDistance`/질량 실측 튜닝. (3개 규모 안정 확인.)
- `AlignTo`가 `FromToRotation`이라 면 법선만 맞추고 roll 근사.
- 결합 지점 = 박스 6면 한정.

# 4. 플레이어 이동 & 시점 — 3인칭 마우스 궤도 카메라 + 카메라 상대 이동

`Assets/PlayerSystem/PlayerFollowCamera.cs` · `PlayerMover.cs` · PR #76 · 이슈 #75
**박진수 승인** (PlayerSystem 수정). 추가/수정 부분 전부 `[mnppi 추가]`/`[mnppi 수정]` 마커, 원본 라인 주석 보존.

## 배경

기믹 3종을 플레이테스트하려다 막힘: (1) 카메라가 고정 각도 팔로우(마우스룩 없음) — 3D를 옆에서만 봄, (2) 스티커·블록 조준이 카메라 화면 중앙 레이캐스트라 3인칭에서 비현실적. → 궤도 카메라 + 카메라 상대 이동 추가 + 기믹 조준 근접화.

## `PlayerFollowCamera.cs` — 마우스 궤도 회전

| 새 필드 | 기본 | 설명 |
|---|---|---|
| `enableMouseOrbit` | `true` | 끄면 기존 고정 팔로우와 **100% 동일**(무회귀) |
| `mouseSensitivity` | `2` | 감도 |
| `minPitch`/`maxPitch` | `-50`/`75` | 상하 한계(뒤집힘 방지) |
| `invertY` | `false` | Y축 반전 |
| `lockCursorOnPlay` | `true` | 커서 락, `Esc` 해제, Game 뷰 클릭 재락 |

- `LateUpdate`에서 마우스 X→`orbitYaw`, Y→`orbitPitch`(클램프) 누적. `Start`에서 `orbitYaw = cameraYawOffset`(90)로 초기화 → 켜기 전 첫 프레임이 기존과 동일.
- **구르기 멀미 방지 특성 유지**: 타깃 "회전"은 여전히 안 읽음. 궤도 각도는 카메라 자신 상태.
- 이질감 수정: 카메라 위치 전체를 SmoothDamp하면 시점 회전 시 궤도 원의 현을 가로질러 미끄러짐 → **추적 지점(`smoothedFollowPoint`)만 SmoothDamp, offset은 즉시 얹음.**
- static 노출: `ViewYaw`(= orbitYaw), `MouseOrbitActive`(= enableMouseOrbit).

## `PlayerMover.cs` — 카메라 상대 이동

```csharp
public bool cameraRelativeInput = true;   // opt-out
private float EffectiveInputYaw()
{
    float? viewYaw = PlayerFollowCamera.ViewYaw;
    if (viewYaw.HasValue && (PlayerFollowCamera.MouseOrbitActive || cameraRelativeInput))
        return viewYaw.Value;   // WASD가 "지금 보는 방향" 기준
    return inputYawOffset;      // 폴백 = 기존 동작
}
```

- 레거시(구) + 토크(정육/정사면체) 두 이동 경로 모두 `inputYawOffset` → `EffectiveInputYaw()`.
- **궤도 카메라가 활성이면 이동도 자동으로 카메라 시점 기준** (둘은 한 세트).
- **유니티 직렬화 이슈 회피**: 기존 씬 컴포넌트에 새 bool을 추가하면 초기값 대신 `false`로 역직렬화되는 경우가 있어(SampleScene의 3 플레이어가 `cameraRelativeInput: 0`으로 저장됨), 값이 아니라 `MouseOrbitActive`(카메라 상태)를 트리거로 삼음.
- `ViewYaw`가 `cameraYawOffset`(90)에서 시작 → `inputYawOffset`도 90인 씬 기본값에선 전환 시 방향 불연속 없음.

## 플레이테스트 결과

- 마우스로 시점 자유 회전, pitch 클램프, `Esc` 커서 해제.
- "궤도 회전 이질적" → 추적 지점만 SmoothDamp로 재구성 후 해소.
- "WASD가 화면과 안 맞음" → `MouseOrbitActive` 트리거 재설계 후 해소. 재컴파일 후 **W가 화면 보는 방향으로 감** 확인.
- 토글 끄면 기존 고정 팔로우 + 월드축 이동으로 무회귀.

## 범위 밖 / 후속

- 카메라 상대 이동은 방향(yaw)만 바꿈. 도달 거리표에 영향 주는 공중 계수·중력 미변경.
- 정사면체 6방향 제약(포탈 PRD §9.3): 포탈 텀블 모드가 이동을 오버라이드하므로 충돌 없음.
- SampleScene 3 플레이어에 새 필드가 `0`으로 직렬화될 수 있으나 `MouseOrbitActive` 트리거 덕에 동작 영향 없음. 원하면 씬에서 `Camera Relative Input` 체크로 명시 가능.

`Assets/Scenes/GimmickDemo_mnppi.unity` 열고 ▶ Play → `Tab`으로 도형 전환하며:
- **마찰 스티커**: 정육면체로 `Ramp_StickerSurface` 경사 옆으로 → `V`(미끄럼)/`Q`+`V`(벨크로) → 경사 밀어올리기로 차이 확인
