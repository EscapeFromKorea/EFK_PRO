# 플레이어 이동 & 시점 — 3인칭 마우스 궤도 카메라 + 카메라 상대 이동

> 작성 mnppi · 2026-09-03 · 담당자 mnppi (박진수 승인 — PlayerSystem 수정)
> 코드: PR #76 (`feat/mnppi-orbit-cam`) · 관련 이슈 #75
> 수정 파일: `Assets/PlayerSystem/PlayerFollowCamera.cs` · `Assets/PlayerSystem/PlayerMover.cs`

## 배경

기믹 3종(마찰 스티커·자유 회전 판·딱딱 블록)을 플레이테스트하려다 막혔다:

1. **카메라가 고정 각도 팔로우** (`PlayerFollowCamera` — 마우스룩 없음). 3D 공간을 옆에서만 봄. 회의 시연은 자유 시점이었으나 커밋된 코드엔 없었음.
2. 스티커·블록 조준이 **카메라 화면 중앙 레이캐스트**라 3인칭에서 작은 표면을 겨누는 게 비현실적.

→ (1) 원신/ZZZ식 **마우스 궤도 3인칭 카메라 + 카메라 상대 이동** 추가, (2) 스티커·블록 조준을 **근접 방식**으로 전환(각 기믹 문서 참고).

**모든 추가/수정 부분은 `[mnppi 추가]` / `[mnppi 수정]` 마커로 감쌌고 원본 라인은 주석 보존** (박진수 리뷰용).

## 1. `PlayerFollowCamera.cs` — 마우스 궤도 회전

### 새 Inspector 필드

| 필드 | 기본값 | 설명 |
|---|---|---|
| `enableMouseOrbit` | `true` | 끄면 기존 고정 팔로우와 **100% 동일** (무회귀) |
| `mouseSensitivity` | `2` | 마우스 이동 1당 회전 각도 계수 |
| `minPitch` / `maxPitch` | `-50` / `75` | 상하 회전 한계 (뒤집힘 방지) |
| `invertY` | `false` | Y축 반전 |
| `lockCursorOnPlay` | `true` | 시작 시 커서 락, `Esc` 해제, Game 뷰 클릭 재락 |

### 동작

- `LateUpdate`에서 마우스 X → `orbitYaw`, 마우스 Y → `orbitPitch`(클램프) 누적.
- `Start`에서 `orbitYaw = cameraYawOffset`(씬 기본 90), `orbitPitch = 0` 초기화 → 켜기 전 시작 프레임이 기존과 정확히 같다.
- **구르기 멀미 방지 특성 유지**: 타깃의 "회전"은 여전히 안 읽는다. 궤도 각도는 카메라 자신의 상태이고 마우스로만 바뀐다.
- `cameraYawOffset`은 이제 "초기 yaw"로 재해석.

### 수정한 기존 라인 (원본 주석 보존)

```csharp
// [수정] LateUpdate + SnapToTarget 2곳
// 기존: Quaternion.AngleAxis(cameraYawOffset, Vector3.up) * offset
Quaternion.Euler(orbitPitch, orbitYaw, 0f) * offset
```
카메라 최종 위치 전체를 SmoothDamp하면 마우스로 시점을 홱 돌릴 때 궤도 원의 현을 가로질러 미끄러지는 이질감이 있어, **추적 지점(`smoothedFollowPoint`)만 SmoothDamp하고 offset은 즉시 얹도록** 재구성했다.

### 노출한 static

```csharp
public static float? ViewYaw       // = orbitYaw. PlayerMover가 카메라 상대 이동에 사용
public static bool MouseOrbitActive // = enableMouseOrbit. 이동/카메라 자동 연동에 사용
```

## 2. `PlayerMover.cs` — 카메라 상대 이동

### 문제

궤도 카메라만으로는 WASD가 월드축 고정(`inputYawOffset`)이라, 시점을 돌리면 "앞"이 화면과 어긋난다.

### 해결

```csharp
public bool cameraRelativeInput = true;   // opt-out

private float EffectiveInputYaw()
{
    float? viewYaw = PlayerFollowCamera.ViewYaw;
    if (viewYaw.HasValue && (PlayerFollowCamera.MouseOrbitActive || cameraRelativeInput))
        return viewYaw.Value;   // WASD가 "지금 보는 방향" 기준
    return inputYawOffset;      // 폴백 = 기존 동작
}
```

- 레거시(구) + 토크(정육/정사면체) 두 이동 경로 모두 `inputYawOffset` → `EffectiveInputYaw()`.
- **궤도 카메라가 활성이면(`MouseOrbitActive`) 이동도 자동으로 카메라 시점 기준** — 둘은 한 세트다.
- **유니티 직렬화 이슈 회피**: 기존 씬 컴포넌트에 새 bool을 추가하면 초기값 대신 `false`로 역직렬화되는 경우가 있어(플레이테스트로 확인 — SampleScene의 3 플레이어가 `cameraRelativeInput: 0`으로 저장됨), `cameraRelativeInput` 값이 아니라 `MouseOrbitActive`(카메라 컴포넌트 상태)를 트리거로 삼는다.
- `ViewYaw`가 `cameraYawOffset`(90)에서 시작 → `inputYawOffset`도 90인 씬 기본값에선 전환 시 방향 불연속 없음.

## 플레이테스트 결과 (2026-09-03, Unity 2022.3.62f3)

- 마우스로 캐릭터 주변 시점 자유 회전, pitch 한계 클램프, `Esc` 커서 해제.
- 처음엔 "궤도 회전이 이질적" → 추적 지점만 SmoothDamp로 재구성 후 해소.
- 처음엔 "WASD 방향이 화면과 안 맞음" → `MouseOrbitActive` 트리거로 재설계 후 해소. 재컴파일 후 **W가 화면 보는 방향으로 잘 감** 확인.
- `enableMouseOrbit` / `cameraRelativeInput` 끄면 기존 고정 팔로우 + 월드축 이동으로 무회귀.

## 범위 밖 / 후속

- **카메라 상대 이동은 방향(yaw)만 바꾼다.** 도달 거리표에 영향을 주는 공중 계수·중력은 안 건드린다.
- 정사면체의 6방향 제약(포탈 PRD §9.3)과의 상호작용: 포탈 텀블 모드(`PlayerRollModeReceiver`, 실행순서 200)가 이동을 오버라이드하므로 충돌 없음. 텀블 모드가 아닐 때의 토크 구르기는 자유 방향이라 카메라 상대와 자연스럽게 맞물림.
- 이 변경 후 `SampleScene`의 3 플레이어 컴포넌트에 새 필드가 `0`으로 직렬화될 수 있으나, `MouseOrbitActive` 트리거 덕에 동작에는 영향 없음. 원한다면 씬에서 `Camera Relative Input` 체크로 명시 가능.
