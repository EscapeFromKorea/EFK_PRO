## 사용 방법

- 결과는 `미진행`, `통과`, `실패`, `확인 불가`, `해당 없음` 중 하나로 기록합니다.
- 실패한 항목은 버그 리포트의 `Bug ID`와 연결합니다.
- 실제 결과에는 판단이 아니라 관찰한 현상을 작성합니다.
- 테스트 빌드와 증거 링크를 반드시 남깁니다.
- 신규 기능 테스트 후에는 관련 기능의 회귀 테스트를 수행합니다.

## 공통 테스트 상세 기준

### TC-SMK-001 — 게임 실행 및 대상 맵 진입

- 사전 조건: 정상 설치된 테스트 빌드
- 절차: 게임 실행 → 새 게임 또는 대상 맵 선택 → 로딩 완료까지 대기
- 기대 결과: 크래시나 무한 로딩 없이 대상 맵에 진입합니다.

### TC-SMK-002 — 세 도형 기본 이동 확인

- 사전 조건: 대상 맵 진입 완료
- 절차: 구의 이동·점프 확인 → 정육면체로 반복 → 정사면체로 반복
- 기대 결과: 세 도형 모두 조작 가능하며 입력이 누락되지 않습니다.

### TC-FUN-001 — 체크포인트 저장 및 리스폰

- 사전 조건: 체크포인트 도달 가능 상태
- 절차: 체크포인트 통과 → 맵 아래로 낙하 → 리스폰 위치와 상태 확인
- 기대 결과: 설정된 판정 시간 후 마지막 체크포인트의 안전 위치로 복귀합니다.

### TC-LVL-001 — 플랫폼 시각과 충돌면 일치

- 사전 조건: 플랫폼이 배치된 구역 진입
- 절차: 세 도형으로 플랫폼 중앙과 가장자리에 접근 → 정지 상태 관찰 → 낙하·재착지 반복
- 기대 결과: 도형이 시각 바닥 위에 자연스럽게 접지하며 뜨거나 파묻히지 않습니다.

### TC-LVL-002 — 벽·모서리·이동 오브젝트 끼임 확인

- 사전 조건: 대상 구역 진입
- 절차: 벽 모서리에 이동 → 점프·회전·동시 입력 → 이동 오브젝트 사이 진입
- 기대 결과: 관통·비정상 가속·복구 불가능한 끼임이 발생하지 않습니다.

### TC-PHY-001 — 반복 충돌 안정성

- 사전 조건: 동적 오브젝트가 있는 구역 진입
- 절차: 세 도형으로 동시에 충돌 → 10회 반복 → 속도·진동·관통 관찰
- 기대 결과: 폭발적 가속·무한 진동·관통 없이 물리가 안정됩니다.

### TC-PRG-001 — 필수 조건 미충족 상태의 클리어 차단

- 사전 조건: 필수 아이템 또는 기믹 미완료 상태
- 절차: 정상 조건을 충족하지 않음 → 출구 위치 접근 → 클리어 판정 확인
- 기대 결과: 필수 조건을 충족하기 전에는 클리어 처리되지 않습니다.

### TC-PRG-002 — 사망·리스폰 후 진행 상태 유지

- 사전 조건: 일부 목표 완료 상태
- 절차: 목표 일부 완료 → 낙사 또는 수동 리스폰 → 문·아이템·진행도 확인
- 기대 결과: 영구 진행 상태는 유지되고 일시적 물리 상태만 안전하게 복구됩니다.

### TC-UX-001 — 첫 진입 목표 인지

- 사전 조건: 사전 설명 없이 새 게임 시작
- 절차: 처음 플레이하는 테스터에게 조작만 안내 → 첫 목표 선택 관찰 → 인지 시간 기록
- 기대 결과: 플레이어가 과도한 시행착오 없이 다음 목표와 상호작용 대상을 식별합니다.
- 추가 기록: 목표 인지 시간, 도움 요청 횟수

### TC-UX-002 — 실패 원인 이해 여부

- 사전 조건: 실패 가능한 기믹 진입
- 절차: 의도적으로 실패 → 시각·음향 피드백 확인 → 테스터에게 원인 질문
- 기대 결과: 플레이어가 실패 원인과 다음 시도에서 바꿀 행동을 설명할 수 있습니다.

### TC-PERF-001 — 일반 플레이 성능 확인

- 사전 조건: 개발 빌드와 측정 환경 준비
- 절차: 대표 구역 10분 플레이 → 물리 오브젝트 집중 구간 반복 → FPS·프레임 타임·메모리 기록
- 기대 결과: 팀이 정한 성능 기준을 만족하며 지속적인 성능 저하가 없습니다.
- 주의: 성능 기준이 확정되지 않았다면 `기획 확인 필요`로 기록합니다.

### TC-REG-001 — 수정 결함 재테스트 및 연관 기능 확인

- 사전 조건: 수정 빌드와 원 결함 티켓 준비
- 절차: 원 재현 절차 수행 → 경계값 수행 → 연결 기능의 정상 경로 수행
- 기대 결과: 원 문제가 재현되지 않고 연결 기능에 새로운 문제가 없습니다.

## The Axiom 테스트 상세 기준

### M1-P06-001 — 상단 스위치로 팀 리프트 발판 상승

- 사전 조건: P06 진입 및 세 도형 정상 상태
- 절차: 정사면체로 `P06_Tetra_TopSwitch` 진입 → 2초 유지 → `P06_TeamLiftGate` 관찰
- 기대 결과: 스위치가 눌리고 팀 리프트 발판이 설정 높이까지 상승합니다.

### M1-P06-002 — 리프트 발판 탑승 안정성

- 사전 조건: `P06_TeamLiftGate` 상승 가능 상태
- 절차: 도형을 발판 위에 배치 → 스위치 작동 → 상승 중 접지·미끄러짐·관통 확인
- 기대 결과: 발판이 평평한 상태로 상승하며 탑승 도형이 관통하거나 비정상 이탈하지 않습니다.

### M1-P12-001 — 최종 점프 발판 작동

- 사전 조건: `P12_FinalJump` 도달 가능 상태
- 절차: 구로 발판 진입 → 정육면체와 정사면체로 반복 → 최고 높이와 착지 확인
- 기대 결과: 세 도형 모두 발판 접촉 시 목표 높이로 발사되고 다음 경로에 착지할 수 있습니다.

### M3-PRG-001 — 세 분기 방문 순서 독립성

- 사전 조건: 신규 진행 데이터
- 절차: 지정 방문 순서로 세 방 완료 → 각 아이템 획득 → 진행도와 Final Gate 확인
- 기대 결과: 방문 순서와 무관하게 중복 없이 `3/3`이 되고 Final Gate가 열립니다.
- 반복 범위: 가능한 방문 순서 6개를 각각 실행합니다.

### M3-OBJ-001 — 동일 아이템 중복 획득 방지

- 사전 조건: 수리 아이템 Trigger 접근 가능 상태
- 절차: 동일 Trigger 반복 진입 → 리스폰 후 재진입 → 진행도 확인
- 기대 결과: 같은 아이템은 한 번만 집계되고 진행도가 추가 증가하지 않습니다.

### M3-RST-001 — 동적 오브젝트 복구와 영구 진행 보존

- 사전 조건: 방 완료 또는 일부 아이템 획득 상태
- 절차: 블록·카트 유실 → 퍼즐 리셋 실행 → 오브젝트와 진행 상태 확인
- 기대 결과: 동적 오브젝트는 안전 위치로 복귀하고 획득 아이템과 완료 상태는 유지됩니다.
