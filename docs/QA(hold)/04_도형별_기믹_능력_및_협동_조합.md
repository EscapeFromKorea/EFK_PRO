# 도형별 기믹 능력 및 협동 조합

- 작성일: 2026-11-03
- 기준: 로컬 `map-integration`의 구현 코드와 도형 스탯 에셋
- 맵1 배치 참고: `Assets/Scenes/Map1_DayDream/map1_codex.unity`
- 목적: 구현된 시스템의 도형별 가능·불가·조건을 확인하고, 맵1 협동 레벨 디자인과 QA에 활용한다.

이 문서는 **현재 구현을 우선**한다. 회의에서 결정했더라도 코드에 반영되지 않은 내용은 구현된 제한으로 취급하지 않는다. 저장된 씬과 코드를 정적으로 확인한 자료이며, 실제 플레이 검증 완료를 의미하지 않는다.

표에는 맵1에 아직 배치되지 않은 시스템도 포함한다. 시스템이 구현되어 있다는 것과 해당 씬에서 사용할 수 있다는 것은 별개다. 각 기능에 필요한 컴포넌트, 참조, Collider, 작동 대상이 연결되어 있어야 한다.

### 회의 결정과 구현의 차이

회의에서는 구·세모의 들어올리기를 금지하고 결합만 허용하기로 했으나, 현재 코드는 **구·세모의 블록 운반을 허용하고 네모의 운반을 금지**한다. 이번 문서는 코드 기준으로 표기했다. 회의 결정에 맞춘 변경은 별도 구현·검증 대상이다.

## 3. 무게·크기·상태로 달라지는 기능

`PlayerWeight.Of`는 다음 기준으로 실효 무게를 계산한다.

```text
실효 무게 = 현재 Rigidbody 질량 × 현재 중력 배율
```

축소·확대는 질량을 바꾸고, 저중력은 실효 무게를 바꾼다. 아래의 무게 제한은 도형 종류를 직접 검사하는 제한과 달리 상태 변화로 통과 여부가 달라질 수 있다.

| 시스템·행동 | 구 기본 상태 | 네모 기본 상태 | 세모 기본 상태 | 확인한 조건·활용 |
|---|---|---|---|---|
| 실에 매달려 스윙 | 가능 | 불가 | 가능 | 맵1 설정은 실효 무게 3 미만. 네모도 축소·저중력으로 가벼워지면 가능 |
| 구름에서 튕기기 | 가능 | 튕기지 않고 눌러앉음 | 가능 | 맵1 구름은 합산 무게 3 미만에서 반발 |
| 구름 과부하 붕괴 | 혼자서는 발생하지 않음 | 혼자서는 발생하지 않음 | 혼자서는 발생하지 않음 | 맵1 기준 합산 무게 3.5 이상에서 붕괴. 네모+구는 4.5, 네모+세모는 4로 기준 초과 |
| 가벼운 도형용 리프트 발판 작동 | 가능 | 불가 | 가능 | `LiftPad` 기본 기준은 개별 도형 실효 무게 2 미만. 축소 네모도 조건을 충족하면 가능 |
| 무게판 문 작동 | 혼자서는 불가 | 가능 | 혼자서는 불가 | 현재 P08은 합산 무게 2.5 이상. 구+세모가 함께 누르면 2.5로 작동 가능 |
| 바람 영향 | 받음 | 기본 기준에서 받지 않음 | 구보다 강하게 받음 | `WindZone` 기본 무게 설정 기준. 네모도 가벼워지면 영향받음 |
| 파괴 가능한 장애물 부수기 | 기본 무게로 불가 | 충돌 속도 충족 시 가능 | 기본 무게로 불가 | `BreakableObject` 기본 기준: 실효 무게 3 이상이면서 상대 충돌 속도 5 이상 |
| 실다리 위 이동 | 가능 | 가능, 더 크게 처짐 | 가능 | `ThreadBridge`는 탑승 무게와 위치에 따라 처짐. 무게별 통행 금지 기능과는 다름 |
| 저중력 버블 이용 | 가능 | 가능 | 가능 | 도형별 중력 배율 설정 적용. 무게 기반 기믹의 판정에도 영향 |
| 축소·확대 패드 이용 | 가능 | 가능 | 가능 | 크기와 질량이 달라지므로 통로 통과뿐 아니라 무게 역할 전환에 사용 가능 |

### 설정값을 구분할 사항

- P08의 현재 무게판 기준은 **2.5**다. `ExitWeightPlate` 코드 기본값 **2.75**와 다르다. 2.75에서는 기본 구+세모의 합산 2.5로 열 수 없다.
- `LiftPad`는 판 위 전체 무게를 합산하는 방식이 아니라 **기준보다 가벼운 개별 바디가 있는지** 검사한다. 구+세모가 함께 올라가 합산 무게가 커졌다는 이유로 꺼지는 방식이 아니다.
- 구름 과부하는 탑승 바디들의 실효 무게를 합산한다. 구+세모는 기본 합산 2.5로 과부하 기준에 못 미치지만, 네모와 다른 도형의 동시 탑승은 과부하를 만들 수 있다.
- 축소·저중력으로 네모를 가볍게 만들면 스윙이나 리프트 발판 사용이 가능해지는 대신, 무게판이나 파괴 조건을 충족하지 못할 수 있다.
- 위 수치는 맵1 씬에서 확인한 설정 또는 명시한 코드 기본값이다. 다른 장치 인스턴스의 Inspector 값이 다르면 결과도 달라진다.

## 5. 기존 시스템으로 구성할 협동 조합 제안

다음은 **기획 제안**이며, 현재 맵1에서 아래 동선이 완성되어 있다는 뜻은 아니다. 배치·설정 후 플레이 검증이 필요하다.

| 조합 | 역할 분담과 진행 | 필요한 배치·설정 |
|---|---|---|
| 세모 핀 + 실다리 | 세모가 먼저 길을 개척하고, 구·네모가 생성된 다리를 건넘 | `ThreadBridge`를 고정 앵커+핀 또는 핀 두 개 방식으로 구성. 핀 위치와 최대 연결 거리 검증 |
| 가벼운 도형용 리프트 발판 + 네모 탑승 | 구 또는 세모가 발판을 유지하여 네모를 운반 | `LiftPad`와 `LiftPlatform` 연결. 발판 담당자의 마지막 합류 경로 필요 |
| 네모 운반 + 최종 무게판 | 팀이 네모를 도착시키면 네모가 출구를 열어줌 | 무게판 기준 설정. 네모도 통과해야 한다면 `latchOpen` 또는 별도 합류 동선 사용 |
| 구+세모 합산 무게판 | 둘이 함께 문을 열고 네모를 먼저 통과시킴 | 기준 2.5 등 합산을 허용하는 값 사용. 남은 두 도형을 반대편에서 회수할 장치 필요 |
| 축소 네모 + 실 스윙 → 크기 복원 + 무게판 | 가벼워져 건넌 뒤 무거워져 팀의 출구를 개방 | 축소·복원 패드와 앵커 배치. 복원 후 무게 조건 재확인 |
| 구 조향 + 세모 장전 + 네모 탑승 | 캐터펄트에서 세 도형이 서로 다른 전용 역할 담당 | 정식 캐터펄트 조립물과 착지 지형 사용. 발사 후 구·세모의 합류 경로 필요 |
| 네모 닻 + 구·세모 스윙 | 네모가 정지해 연결점을 제공하고 가벼운 도형이 이동 | 현재 코드는 네모의 비조작 상태를 요구. 실제 멀티에서 정지 중인 조작 플레이어를 인정하려면 판정 변경 검토 필요 |
| 네모 이동 보조 + 세모 모래시계 발동 | 네모가 장치를 이동시키고 세모가 충돌해 감속 구역을 작동 | 이동 잠금·도형 발동 게이트를 함께 사용. 충돌 운동량과 경로 검증 |

## 6. QA 및 구현 전 확인 사항

- 전용 능력인지 무게 조건인지 구분한다. 무게 조건은 축소·확대·저중력과 여러 도형의 동시 탑승으로 우회할 수 있다.
- 한 명을 발판에 남기는 구성에는 그 플레이어가 마지막에 합류할 경로를 포함한다.
- 같은 문에 여러 발판이 각자 상태를 전달하는 것만으로 OR·AND 조건이 만들어지지 않는다. 현재 P08은 두 무게판이 같은 문에 연결되어 있으므로 입력 덮어쓰기 가능성을 확인한다.
- 공유 체크포인트와 수동 복귀로 미통과 도형이 합류하여 협동을 건너뛸 수 있는지 확인한다.
- `ThreadCubeAnchor` 등 비조작 상태를 요구하는 코드는 Tab 전환 테스트와 실제 동시 조작 멀티플레이를 구분해 검증한다.
- 구·세모 들어올리기 금지와 상호작용 키 통일은 회의 결정만으로 구현 완료로 판단하지 않는다.
