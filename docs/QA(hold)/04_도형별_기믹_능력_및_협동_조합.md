# 도형별 기믹 능력 및 협동 조합

- 최초 작성일: 2026-11-03
- 재검토 기준: 로컬 현재 브랜치 `develop`, 커밋 `daa42f6`
- 대상: 현재 브랜치에 구현된 시스템과 도형 스탯 에셋
- 목적: 각 도형의 가능·불가·조건부 능력을 구분하여 협동 레벨 디자인 및 QA에 활용한다.

이 문서는 **실행 코드와 에셋을 확인한 정적 분석 결과**다. 실제 플레이 검증 완료나 네트워크 멀티플레이 지원 완료를 의미하지 않는다. 시스템이 존재해도 씬에 필요한 컴포넌트·Collider·참조·이벤트를 연결해야 작동한다.

현재 `develop`에는 이전 문서가 참고한 `Assets/Scenes/Map1_DayDream/map1_codex.unity`가 없다. 따라서 이전 맵1의 P08 기준값이나 특정 배치를 현재 상태로 단정하지 않고, 아래 표는 **코드 기본값**을 기준으로 정리한다. 실제 씬 Inspector 값이 다르면 판정도 달라진다.

## 1. 이전 문서에서 달라진 핵심 내용

| 항목 | 이전 문서 | 현재 브랜치에서 확인한 구현 |
|---|---|---|
| 블록 들어올리기 | 구·세모 가능, 네모 불가 | **네모만 가능. 구·세모 불가** |
| 손 상호작용 | 기능별 기존 입력을 전제로 설명 | `InteractionController`의 기본 손 채널은 **E**, 장비 채널은 **V**. 탭·홀드 중 후보를 선택해 실행 |
| 무게판 기준 | 맵1 P08의 2.5 적용 | 현재 브랜치 코드 기본값 **2.75**. 구+세모 기본 합산 2.5로는 부족 |
| 맵1 씬 | `map1_codex` 배치 참고 | 현재 브랜치에는 해당 씬이 없어 배치 상태는 미확인 |
| 시스템 범위 | 이동·물리 기믹 중심 | 역할 점유·문답·배선·격리 구출·전력 유지·감시·함정·구간 복귀도 포함 |

블록 들기 제한은 이전 문서에서 말한 회의 결정과 다른 미반영 상태가 아니라, **현재는 네모 전용으로 구현된 상태**다. 다만 E 통합은 상호작용 채널을 뜻하며, 이동·점프·마우스 조준·휠·패널 내부 입력까지 전부 E라는 뜻은 아니다.

## 2. 표기와 기본 능력치

- ○: 도형 종류에 의한 제한 없이 가능. 장치 배치와 일반 상호작용 조건은 필요하다.
- ×: 표에 명시한 도형 제한 또는 기본 무게 조건 때문에 불가.
- △: 추가 상태·무게·거리·역할·설정 조건을 충족해야 가능.
- 기본 상태: 기본 크기, 일반 중력, 별도 효과가 없는 상태.

| 항목 | 구 | 정육면체 — 네모 | 정사면체 — 세모 |
|---|---:|---:|---:|
| 이동속도 | **7 — 가장 빠름** | 3.5 — 가장 느림 | 5 |
| 목표 점프 높이 | 1.6 | 1.2 — 가장 낮음 | **2 — 가장 높음** |
| 질량 | 1.5 | **3 — 가장 무거움** | 1 — 가장 가벼움 |

근거: `Assets/PlayerSystem/ShapeStats/{SphereStats,CubeStats,TetrahedronStats}.asset`의 실제 값. 점프 높이는 스탯 목표값이며 중력·기믹·접지·조작 잠금 등에 따라 실제 이동은 달라진다.

## 4. 무게·크기·중력에 따른 가능·불가

`PlayerWeight.Of`의 실효 무게는 다음과 같다.

```text
실효 무게 = 현재 Rigidbody 질량 × 현재 중력 배율
현재 질량 = 기본 스탯 질량 × 현재 크기 비율
```

크기 비율에 대한 질량 변화는 현재 코드에서 선형이다. 길이를 두 배로 키운다고 질량이 여덟 배가 되는 방식은 아니다.

| 시스템·행동 | 구 기본 상태 | 네모 기본 상태 | 세모 기본 상태 | 코드 기본 조건 / 조건이 바뀌는 경우 |
|---|---|---|---|---|
| 실 매달림·스윙 | ○ | × | ○ | 실효 무게 **3 미만**. 축소·저중력 네모는 조건 충족 시 가능 |
| 구름 반발 | ○ | × — 눌러앉음 | ○ | 탑승 합산 무게 **3 미만**에서 반발. 네모도 가벼워지면 가능 |
| 구름 과부하 붕괴 | 혼자서는 불가 | 혼자서는 불가 | 혼자서는 불가 | 합산 무게 **3.5 이상**에서 붕괴. 네모+구=4.5, 네모+세모=4는 기준 초과 |
| 가벼운 도형용 리프트 발판 작동 | ○ | × | ○ | `LiftPad`는 **개별 실효 무게 2 미만**인 바디가 있으면 작동. 축소 네모도 가능 |
| 무게판 문 작동 | 혼자서는 × | ○ | 혼자서는 × | `ExitWeightPlate.requiredWeight=2.75`. 구+세모 합산 2.5로도 부족 |
| 바람 영향 | 받음 | 기본값에서 받지 않음 | 구보다 강하게 받음 | `heavyWeightCutoff=3` 기준. 가벼워진 네모도 바람 영향 가능 |
| 장애물 파괴 | 기본 무게로 × | △ | 기본 무게로 × | `BreakableObject`: 실효 무게 **3 이상 AND 상대 충돌 속도 5 이상**. 확대 구·세모도 무게와 속도 충족 시 가능 |
| 실다리 건너기 | ○ | ○ — 더 크게 처짐 | ○ | 탑승 무게·위치에 따라 처짐. 무게만으로 통행을 금지하는 기능은 아님 |
| 저중력 버블 이용 | ○ | ○ | ○ | 도형별 중력 배율 적용. 낮아진 실효 무게가 실·구름·무게판 등에 영향 |
| 축소·확대 | ○ | ○ | ○ | 크기와 질량 변화. 통로와 무게 조건을 함께 바꿈 |
| 시소·물리 회전판에 하중 가하기 | ○ | ○ | ○ | Rigidbody/HingeJoint의 물리 반응. 네모 전용 발동이나 세모 전용 쐐기 잠금 판정은 아님 |
| 관성 축전기 충전 | △ | △ | △ | `InertiaCapacitor`는 도형 종류 대신 충돌 충격량 사용. 최소 충격량·접촉·재충전 조건 적용 |

### 무게 조합 판정 예시

| 기본 상태 조합 | 합산 무게 | 무게판 기본 기준 2.75 | 구름 붕괴 기준 3.5 |
|---|---:|---|---|
| 구 단독 | 1.5 | 열 수 없음 | 붕괴하지 않음 |
| 세모 단독 | 1 | 열 수 없음 | 붕괴하지 않음 |
| 네모 단독 | 3 | 열 수 있음 | 붕괴하지 않고 눌러앉음 |
| 구+세모 | 2.5 | 열 수 없음 | 붕괴하지 않음 |
| 네모+세모 | 4 | 열 수 있음 | 붕괴 조건 충족 |
| 네모+구 | 4.5 | 열 수 있음 | 붕괴 조건 충족 |

`LiftPad`는 합산 무게판이 아니다. 구+세모가 동시에 올라갔을 때 합계 2.5라는 이유로 작동을 거부하지 않는다. 반면 구름과 `ExitWeightPlate`는 합산을 사용한다.

`ExitWeightPlate`를 2.5로 조정하면 구+세모의 동시 작동을 허용할 수 있지만, 이는 **기본 동작과 구분되는 레벨 설정 제안**이다.

## 5. 세 도형 모두 사용할 수 있는 장치

아래 ○는 도형 전용 제한이 없다는 의미다. 접근 범위·입력 잠금·점유·유효한 대상 같은 일반 조건은 충족해야 한다.

| 시스템·행동 | 구 | 네모 | 세모 | 구현 범위와 제한 |
|---|:---:|:---:|:---:|---|
| 일반 문 발판 누르기 | ○ | ○ | ○ | `PadTrigger`는 무게 기준이 아님. 유효 상호작용 아이템도 허용 |
| 레버 밀기 | ○ | ○ | ○ | 물리 접촉과 이동 방향에 따라 조작 |
| 무지개 다리 스위치 누르기 | ○ | ○ | ○ | Hold 또는 시간제 설정. 상호작용 아이템도 허용 |
| 점프패드·가속패드 이용 | ○ | ○ | ○ | 도형 전용 판정 없음 |
| 리프트에 탑승하여 운반되기 | ○ | ○ | ○ | 발판을 작동시키는 무게 제한과 탑승 제한은 별개 |
| 레일카 탑승 | ○ | ○ | ○ | `RailCartRider`에 도형 전용 제한 없음. 거리·점유 조건 필요 |
| 태엽 활성화 발판 누르기 | ○ | ○ | ○ | `WindupActivationPad`의 유지 판정. 패들로 태엽을 감는 행동과 별개 |
| 블록 결합·분리 | ○ | ○ | ○ | `SnapBlockController`: 거리·각도·구조물 제한 적용. 들기와 별개 |
| 스티커 부착·제거 | ○ | ○ | ○ | `PlayerStickerCarrier`와 허용 표면·재고 조건 필요 |
| 에너지볼 줍기·공간 포탈 설치 | ○ | ○ | ○ | 한 번에 한 볼 소지. 설치는 유효한 `PortalSurface`와 공간 조건 필요 |
| 공간 포탈 통과 | ○ | ○ | ○ | `SpacePortal`의 연결·진입·출구 조건 필요. 격자 구르기 전환 `Portal`과 다른 시스템 |
| 가변 포탈 패널 레버 밀기 | ○ | ○ | ○ | `PanelLever`가 플레이어 충돌로 이동·회전 구동 |
| 관성 축전기 수동 방출 | ○ | ○ | ○ | 근거리 E 홀드, 저장량·출력 수신 장치 필요 |
| 동기화 오브젝트에 힘·하중 가하기 | ○ | ○ | ○ | 페어 ID·설정된 shapeKind·모드가 맞는 장치끼리 동기화. shapeKind는 페어 장치의 설정이며 조작 플레이어 전용 제한이 아님 |

### 입력 구분

| 행동 | 현재 기본 입력·방식 |
|---|---|
| 탑승·도킹·들기·실 연결/해제·핀 설치·역할 패널·배선 등 손 상호작용 | 중앙 Hand 채널 **E 탭/홀드**. 가까운 후보·우선순위·상태에 따라 한 액션 선택 |
| 블록 결합·분리, 핀 전체 회수, 축전기 수동 방출 | 해당 제공자가 **E 홀드** 액션을 등록 |
| 스티커 | 중앙 Gear 채널 **V 탭/홀드**. 구체 액션은 제공자 설정에 따름 |
| 이동·점프·도형 전환·휠·포탈 조준·패널 내부 선택 | 각 기능의 별도 입력. 모두 E로 바뀐 것은 아님 |

예전 주석에 C/F/G/T가 남아 있어도 해당 기능의 `CollectActions`와 실제 입력 처리 경로를 기준으로 확인해야 한다.

## 6. 도형 대신 역할·퍼즐 상태로 제한되는 협동 시스템

이 표의 △는 세 도형 모두 역할을 맡을 수 있지만, 배정·위치·문제·진행 조건이 필요하다는 뜻이다. 특정 도형의 고유 능력으로 취급하지 않는다.

| 시스템 | 구 | 네모 | 세모 | 할 수 있는 것 / 할 수 없는 것 |
|---|:---:|:---:|:---:|---|

## 8. 구현된 능력으로 구성할 협동 조합 제안

다음은 시스템 재사용을 전제로 한 **기획 제안**이다. 현재 씬에서 해당 동선이 완성됐다는 뜻은 아니다.

| 조합 | 도형별 할 일 | 기존 구현으로 가능한 부분 | 추가 배치·검증 |
|---|---|---|---|
| 네모 운반 + 전원 결합 | 네모가 독립 블록을 운반하고 구·세모도 결합 작업 참여 | 네모 전용 들기, 전 도형 결합 | 운반 상한·결합 자세·발판으로 악용 가능한 경로 검증 |
| 세모 핀 + 실다리 | 세모가 선행하여 구·네모의 길 생성 | 고정 앵커+핀, 핀 두 개 방식 | 설치 벽·연결 거리·핀 회수 시 팀 안전 |
| 가벼운 도형 발판 + 네모 운반 | 구/세모가 리프트를 작동시키고 네모가 탑승 | `LiftPad` + `LiftPlatform` | 마지막 발판 담당자의 합류 경로 |
| 네모 도착 + 무게문 개방 | 다른 도형이 네모 이동을 돕고 네모가 출구 개방 | 기본 2.75 무게판, latch 설정 | 축소/저중력 해제 및 네모 자신의 통과 경로 |
| 축소 네모 스윙 + 복원 후 무게판 | 네모가 가벼워져 건넌 뒤 무거워져 팀 경로 개방 | 크기별 질량, 무게 기반 스윙·무게판 | 축소/복원 위치와 실효 무게 변화 |
| 구+세모 공동 무게판 | 둘이 함께 문을 열고 네모 선행 | 합산 무게판 | **기준을 2.5로 조정해야 함**. 기본 2.75에서는 불가 |
| 구 조향 + 세모 장전 + 네모 탑승 | 캐터펄트의 세 도형 전용 역할 수행 | 기존 캐터펄트 3역할 | 발사 후 조향·장전 담당자의 합류 |
| 네모 닻 + 구/세모 스윙 | 네모가 연결점을 제공하고 다른 도형이 이동 | 네모 정지 앵커·가벼운 도형 스윙 | 현재 비조작 조건은 실제 동시 조작 환경에 맞춰 검토 |
| 네모 이동 보조 + 세모 모래시계 발동 | 네모가 장치를 옮기고 세모가 충돌 발동 | 이동 잠금과 발동 도형 분리 | 운동량·작동 위치·제한시간 동선 |
| 충돌 충전 + 장치 구동 + 탑승 | 한 도형이 축전기를 충전하고 다른 도형이 이동 장치 이용 | 축전기 + `IWindupReceiver` | 이 조합 자체에는 도형 전용 제한 없음. 출력량·이동거리 조정 |
| 정보 담당 + 조작 담당 + 유지 담당 | 책/단서, 문답/배선, 전력 유지 역할 분담 | 역할 슬롯·문답·배선·전력 유지 | 어느 도형도 맡을 수 있음. 초반 튜토리얼보다 후반 적용 검토 |

맵1 적용 시 초반에는 전 도형 공통 이동과 단일 기믹을 학습시키고, 중반부터 전용 능력 또는 무게 차이를 조합하는 편이 적합하다. 발판 유지 역할만 반복하기보다 운반·길 생성·문 개방을 번갈아 배치한다.

## 9. 구현·QA 확인 사항

- 도형 종류 제한과 무게 제한을 별도로 검증한다. 크기·중력 변경이 도형 종류까지 바꾸지는 않는다.
- 모든 ○ 항목도 장치/컴포넌트 배치가 필요하다. 현재 브랜치에 없는 맵1 씬의 배치 상태는 별도 확인한다.
- 여러 스위치를 같은 문에 연결하는 것만으로 OR/AND가 성립하지 않는다. `SetPadPressed(bool)`에 각 장치가 독립 전달하면 상태 덮어쓰기가 가능하다.
- Hold 장치에는 마지막 조작자의 합류 경로를 포함한다.
- 체크포인트 공유·수동 복귀·원격 체크포인트와 협동 필수 동선이 충돌하지 않는지 확인한다.
- 시소의 쐐기 고정은 물리 접촉 결과다. “세모 전용 고정 성공” 상태를 코드가 별도로 보장한다고 가정하지 않는다.
- `SyncObject.shapeKind`는 장치 페어 일치 조건이다. 네모 플레이어만 작동시키는 스위치라는 뜻이 아니다.
- 캐릭터 조준 레이저의 록온 제외와 피해 면역을 혼동하지 않는다.
- 과거 주석보다 실제 분기·입력 제공자·스탯 에셋·Inspector를 우선한다.
